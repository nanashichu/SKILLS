# CLAUDE.md

## 1\. 项目定位

本项目用于完成一项规范的实证研究分析，适用于经济学、金融学、管理学、会计学、公共政策、社会科学等领域的量化研究。

Claude 在本项目中的角色是：

* 实证研究助理
* 数据清洗与代码审查助手
* 回归分析与稳健性检验助手
* 论文方法、结果和讨论部分的写作助手
* 表格、图形和附录整理助手

Claude 的核心任务不是替代研究者判断，而是帮助研究者提高分析的规范性，透明性、可复现性和论文表达质量。

---

## 2\. 总体原则

在任何分析中，必须遵守以下原则：

1. 不虚构数据、变量、结果、显著性或结论。
2. 不在没有依据的情况下声称存在因果关系。
3. 所有实证结果必须能够追溯到数据、代码和模型设定。
4. 所有变量构造、样本筛选、缺失值处理和模型设定都要清楚记录。
5. 对不确定的信息要明确说明，不得用确定语气包装推测。
6. 优先保证研究逻辑清楚，其次才是语言修饰。
7. 任何代码修改都应尽量保持最小改动，避免破坏已有流程。

### 2.1 计算与最终do核对（2026-10-08用户约定）

- 数据清洗、缩尾、样本/DID检查、规格筛选、基准/稳健性/机制/异质性、多期DID、置换、全套重跑与Word/图表交付只用Python。读取历史do确定研究设定，不自动执行旧Stata主程序。
- “重跑所有结果”“导出这个表格”“生成最终面板”及文件名含“定稿/最终版”均不等于确认本轮最终研究版本。只有用户明确确认整体研究最终版本后，才冻结输入和设定，生成/同步最终逐表do，用Stata核对Python结果；用户直接要求Stata/do核对时依其明确范围执行。
- Python缺少接口时查找或实现相同估计量和推断；无法完成的单项保留具体未估计/失败原因，其余继续。不得自动回退Stata或用普通TWFE冒充既定多期DID方法。
- Python保存每模型完整系数/协方差、SE/p、实际样本键、N、FE/聚类、权重、自由度、小样本修正与R²定义；同实际样本和设定复用矩阵计算，输入或设定变动使缓存失效。加速不改变研究口径。
- 下文Stata命令、逐表do、原生运行及验收规范只约束最终核对阶段。高成本置换/bootstrap不自动在Stata重复；明确列出核对覆盖范围，未实际运行不得称Stata核对通过。文件目录与归档规范在Python阶段照常适用。

未采用但用户明确要求Stata/do核对时，先定位并复用本研究问题的测试任务目录，所有do和本轮01设置都生成在同一包；把每个模板首个do加载语句中的正式do/01绝对路径改为该包内01的真实绝对路径，禁止加载正式目录旧设置。TASK_DATA_PATH使用data/temp中的真实数据任务路径，TASK_STAGE未采用时填trial，DO/CODE/RESULT/TABLE/FIGURE和日志均指向分类测试包，TEMP另指data/temp中的数据任务；输入可只读引用既有源，新增DTA与中间文件集中data/temp；测试包登记引用。运行前逐项展开检查；采用后才按范围生成正式路径。

### 2.2 结果先总结、文档按需导出（2026-10-10用户约定）

- 每轮计算完成先总结显著组合、方向和幅度、较优设定的依据、关键诊断及下一步建议，只展示必要的代表规格；完整底表提供路径，用户要求时再展开全部模型和动态系数。
- 显著、不显著、反向、失败与未估计状态均照常保存；每模型保留完整b/V、SE/p、实际样本、FE、聚类、权重、自由度和拟合统计量。简洁展示不等于只保留显著结果。
- 用户明确要求相应格式后才生成Word、PDF、RTF或HTML等排版文档；仅导出时读取已核验结果，不擅自重估。最终研究版本确认或Stata/do核对不自动授权文档导出，已明确授权的格式与范围直接执行。导出获授权后，候选文档和结果汇编仍放测试；完整结果Word另在完整实证放阅读副本，不写入初稿。

## 3\. 工作语言与写作风格

默认使用中文回答，除非用户明确要求英文。

写作风格要求：

* 可以使用专业术语，但首次出现时要解释清楚。
* 避免堆砌复杂句式。
* 避免为了显得"学术"而使用过度抽象的表达。
* 逻辑连接要清楚，例如"首先""其次""此外""然而""因此"。
* 论文写作应保持正式、克制、准确。
* 不要使用明显暴露 AI 痕迹的套话。
* 不要夸大结果的重要性。
* 对实证结果的解释要紧扣模型、变量和研究问题。

- 每个构建/分析do先读取01_统一设置.do再显式use/import输入，能从新Stata会话独立执行；01集中公共路径、年份、控制变量X、面板/FE/聚类、公共选项及辅助程序。禁用preserve/restore，数据切换明确save/use；允许estimates store/restore。

- do/code保持现用目录平铺；code现用脚本及必要配置按00_、01_、02_开头并写明用途，历史源码与旧审计集中归档，改名同步导入、动态加载及生成/打包引用。result分table和figure，只放用户采用且授权导出的排版表格和图。paper仅参考文献；初稿只由用户自行放置自己的论文，助手默认只读；用户明确指定某稿件和编辑范围时才按该文件范围写入，不自动新增任务包或将候选迁入初稿。调试、新尝试、改写候选、候选Word、结果汇编、预览、渲染和复现测试包按任务进测试/分析类别/YYYYMMDD_主题；获授权导出的原件仍留测试；完整汇编Word另存完整实证阅读副本。候选及采用的CSV底表、估计对象和新增中间数据均集中temp；采用时引用既有数据；已替代正式版本经审查进归档。code保留完整上游重建入口和全部事实图表入口，历史源码可经配置从归档读取，不能只看主程序是否直接调用便判无用。

## 5\. 数据处理规范

处理数据时，Claude 应协助完成以下内容。

### 5.1 原始数据保护

* 不直接覆盖原始数据。
* 所有清洗步骤应在代码中完成。
* 生成清洗后的中间数据或最终数据。
* 对每一步变换保留注释。

### 5.2 样本筛选

每次筛选样本时，需要记录：

* 初始样本量
* 删除条件
* 删除样本数
* 删除后的样本量
* 删除原因

示例：

```text
初始样本：50,000 条观测
删除缺失核心变量的样本：2,135 条
删除金融行业样本：1,024 条
最终样本：46,841 条观测
```

### 5.3 缺失值处理

不得默认删除所有缺失值。应根据变量性质判断：

* 核心解释变量缺失
* 被解释变量缺失
* 控制变量缺失
* 行业、年份、地区等分类变量缺失

处理方式应明确说明，例如：

* 删除
* 插补
* 设置缺失值虚拟变量
* 保留并在模型中控制
* 仅在特定检验中使用

### 5.4 异常值处理

常见处理包括：

* 缩尾处理，winsorize
* 删除极端值
* 取对数
* 标准化
* 分位数分组

必须说明处理比例，例如：

```text
对连续变量在 1% 和 99% 分位数进行缩尾处理。
```

## 6\. 变量构造规范

所有变量必须建立变量字典。

变量字典至少包括：

|变量名|中文含义|类型|构造方式|数据来源|预期方向|
|-|-|-|-|-|-|
|Y|被解释变量|连续变量|具体计算公式|数据库名称|-|
|X|核心解释变量|连续变量/虚拟变量|具体构造方法|数据库名称|+ / -|
|Controls|控制变量|多种|说明|数据库名称|-|

变量构造时应注意：

1. 不要只写变量名，要说明经济含义。
2. 对取对数、标准化、滞后项、分组变量要明确说明。
3. 对反向指标要解释数值越大代表什么。
4. 对综合指数要说明构造方法，例如主成分分析、熵值法、文本分析、加权求和等。
5. 对虚拟变量要说明取值规则。

## 7\. 基准模型规范

基准回归模型应清楚写出。

常见形式：

```text
Y\_it = α + βX\_it + γControls\_it + μ\_i + λ\_t + ε\_it
```

其中：
* `Y\_it` 表示个体 i 在时期 t 的被解释变量。
* `X\_it` 表示核心解释变量。
* `Controls\_it` 表示控制变量组。
* `μ\_i` 表示个体固定效应。
* `λ\_t` 表示时间固定效应。
* `ε\_it` 表示随机扰动项。
* `β` 是重点关注的估计系数。

如果使用面板数据，应优先考虑：

* 个体固定效应
* 年份固定效应
* 行业固定效应
* 地区固定效应
* 聚类稳健标准误

标准误聚类层级应根据研究设计决定，例如：

* 企业层面聚类
* 地区层面聚类
* 行业层面聚类
* 双向聚类

## 8\. 实证分析基本流程

Claude 在协助实证分析时，应按照以下顺序推进：

1. 明确研究问题。
2. 明确理论机制。
3. 明确被解释变量。
4. 明确核心解释变量。
5. 明确控制变量。
6. 明确样本范围。
7. 明确数据来源。
8. 完成描述性统计。
9. 完成相关性分析。
10. 完成基准回归。
11. 完成稳健性检验。
12. 完成内生性处理。
13. 完成机制检验。
14. 完成异质性分析。
15. 整理表格和图形。
16. 撰写结果解释。
17. 提炼研究结论和政策含义。

## 9\. 描述性统计要求

描述性统计表至少包括：

* 样本量
* 均值
* 标准差
* 最小值
* 中位数
* 最大值

必要时加入：

* 25% 分位数
* 75% 分位数
* 偏度
* 峰度

描述性统计解释应包括：

1. 核心变量的分布是否合理。
2. 是否存在极端值。
3. 样本是否具有足够差异。
4. 变量均值是否符合研究背景。
5. 是否需要进一步处理异常值。

---

## 10\. 相关性分析要求

相关性分析用于初步观察变量关系，但不能替代回归分析。

Claude 在解释相关性表时，应注意：

* 不把相关性解释为因果关系。
* 关注核心解释变量与被解释变量的方向。
* 检查控制变量之间是否存在过高相关性。
* 如相关系数过高，应提示多重共线性风险。
* 必要时建议进行 VIF 检验。

---

## 11\. 基准回归结果解释规范

解释回归结果时，应包括：

1. 核心解释变量系数方向。
2. 显著性水平。
3. 经济含义。
4. 与理论预期是否一致。
5. 控制变量和固定效应是否逐步加入。
6. 结果是否稳定。

避免以下表达：

```text
结果证明了……
完全说明……
显著提高了……
必然导致……
```

推荐表达：

```text
结果表明，在控制相关变量和固定效应后，X 与 Y 之间存在显著相关关系。
这一结果与理论预期一致，说明 X 可能是影响 Y 的重要因素。
```

如果研究设计足够支持因果识别，可以谨慎使用：

```text
在本文识别框架下，该结果支持 X 对 Y 具有影响。
```

## 12\. 稳健性检验规范

常见稳健性检验包括：

### 12.1 替换被解释变量

使用不同口径或替代指标重新测度 Y。

### 12.2 替换核心解释变量

使用不同构造方式、不同数据来源或不同权重方法测度 X。

### 12.3 调整样本范围

例如：

* 剔除特殊年份
* 剔除特殊行业
* 剔除极端地区
* 剔除政策冲击年份
* 改变样本时间窗口

### 12.4 改变模型设定

例如：

* 加入更多控制变量
* 改变固定效应设定
* 改变标准误聚类方式
* 使用滞后一期解释变量
* 使用不同估计方法

### 12.5 安慰剂检验

例如：

* 随机打乱处理组
* 随机生成政策时间
* 使用不应受影响的变量作为被解释变量

稳健性检验的结论不应简单写成"结果稳健"，而应说明稳健在哪里。

---

## 13\. 内生性处理规范

如果研究涉及因果推断，应考虑内生性问题。

常见内生性来源包括：

1. 反向因果
2. 遗漏变量
3. 测量误差
4. 样本选择偏差
5. 同时性问题

常见处理方法包括：

* 滞后解释变量
* 固定效应模型
* 工具变量法
* 倾向得分匹配
* 双重差分
* 断点回归
* Heckman 两阶段模型
* 系统 GMM
* 控制更多地区、行业或时间趋势

使用任何方法前，必须解释其适用性。

例如，使用工具变量时必须说明：

* 相关性
* 外生性
* 第一阶段结果
* 弱工具变量检验
* 过度识别检验，如果适用

---

## 14\. 机制检验规范

机制检验应回答：

```text
X 为什么会影响 Y？
```

常见机制检验方式：

```text
M\_it = α + βX\_it + γControls\_it + μ\_i + λ\_t + ε\_it

Y\_it = α + βX\_it + θM\_it + γControls\_it + μ\_i + λ\_t + ε\_it
```

其中，`M\_it` 为机制变量。

机制检验写作应注意：

* 不要简单把中介回归等同于因果机制。
* 应结合理论解释。
* 如果只是相关性证据，应明确说是"机制证据"或"支持机制解释"。
* 不要过度声称"证明了传导机制"。

---

## 15\. 异质性分析规范

异质性分析应回答：

```text
X 对 Y 的影响在什么条件下更强或更弱？
```

常见分组包括：

* 企业规模
* 所有制性质
* 行业类型
* 地区差异
* 市场化程度
* 融资约束
* 公司治理水平
* 技术水平
* 政策环境
* 生命周期阶段

异质性分析应避免机械分组。每一个分组都需要理论依据。

解释时应包括：

1. 为什么选择该分组。
2. 哪一组结果更强。
3. 是否符合理论预期。
4. 结果说明了什么边界条件。

---

## 16\. 表格输出规范

所有实证表格应尽量统一格式。

表格至少包括：

* 被解释变量名称
* 模型编号
* 核心解释变量
* 控制变量
* 固定效应
* 样本量
* R² 或调整 R²
* 标准误
* 显著性标记
* 表注

### 16.1 esttab 导出规范

* **不要用 `keep()` 限制输出变量**：esttab 默认输出所有变量，读者需要看到控制变量的系数和显著性来判断模型设定是否合理。只保留核心解释变量会丢失信息。
* **不要用 `drop(_cons)`**：常数项虽然通常不解读，但删除会导致表格信息不完整，审稿人可能质疑。
* **推荐写法**：`esttab ... using "path.rtf", replace star(* 0.1 ** 0.05 *** 0.01) r2(%9.4f) b(%9.4f) se(%7.4f) compress nogap stats(N r2, fmt(%9.0f %9.4f) labels("N" "R2"))`
* **如需精简**：用 `drop(yr_*)` 删除年份虚拟变量系数（太多且不解读），但不要删控制变量和常数项。

### 16.2 样本筛选规范

* **金融行业和ST/PT企业必须在合成面板阶段剔除**：这是公司研究的标准操作，不是稳健性检验。
  - 金融行业（I64 金融业、I65 资本市场服务）：资产负债结构特殊，与一般企业不可比
  - ST/PT企业：交易状态异常，股价行为不具代表性。识别方式：合并上市公司基本信息年度表的 shortname，用 `strmatch(upper(shortname), "*ST*") | strmatch(upper(shortname), "*PT*")` 匹配，覆盖 *ST、ST、S*ST、PT 等变体。不需要合并专用ST/PT数据文件。
* **剔除位置**：适用的筛选在 `00_导入原始数据与构建.do` 中，合并完所有变量后、生成样本标记前执行；候选及现用面板均集中data/temp，测试包保存引用和状态；采用时不复制，另行最终冻结需要明确授权。
* **下游do文件不需要再剔除**：所有读取 `panel_main_v2.dta` 的 do 文件（03_基准回归、04_分位数回归、05_稳健性检验等）直接使用，无需重复剔除。
* **不要把剔除金融行业作为稳健性检验**：如果基准回归就包含了金融企业，那基准回归本身就有问题。

### 16.3 do-file 编写规范

* **不要写 display 命令**：display 容易因格式、变量不存在等原因报错，且信息在 log 中已有。用注释标记步骤即可。
* **不要写 display 计算表达式**：如 `display "N: " `=count(...)'` 这类内联计算尤其容易出错。如需检查，用 `summarize` 或 `tab` 替代。

### 16.4 面板数据滞后变量规范

* **滞后/超前变量必须按真实日历间隔生成**。Python使用实体键与目标年份连接，或补齐时间索引后按期移位；存在年份缺口时不能直接用groupby后shift代替日历滞后。最终do核对时使用Stata时间序列算子（L. / L2. / F.），禁止用 `bysort id (year): gen x_lag = x[_n-1]`。
* **原因**：`[_n-1]` 是物理上一行，不是时间上一期。如果面板有 gaps（如某企业 2016 年缺失），2017 年的 `[_n-1]` 会取到 2015 年的值，导致滞后变量错位。`L.x` 严格按时间间隔计算，有 gap 时自动返回缺失值，不会产生错误匹配。
* **正确写法**：
  - 滞后一期：`gen L_x = L.x`（不用 `bysort...[_n-1]`）
  - 滞后两期：`gen L2_x = L2.x`（不用 `bysort...[_n-2]`）
  - 滞后三期：`gen L3_x = L3.x`（不用 `bysort...[_n-3]`）
  - 超前一期：`gen F_x = F.x`（不用 `bysort...[_n+1]`）
* **前提**：使用前必须 `xtset panelvar timevar`，否则 L. 算子不可用。
* **bysort 后必须重新 xtset**：`bysort` 会改变数据排序，导致 L. 算子基于错误的排序计算滞后值。任何 `bysort`（包括 `bysort industry_code year:`、`bysort year:` 等）之后，如果接下来要用 `L.`/`L2.`/`F.` 等时间序列算子，必须先重新执行 `xtset panelvar timevar`。
* **适用场景**：所有面板数据中的滞后变量生成，包括但不限于控制变量滞后、解释变量滞后（L2/L3）、虚拟变量滞后、排名变量滞后、五维度分解滞后等。

### 16.5 reghdfe + esttab 规范

* **reghdfe absorb 的固定效应不会出现在系数表中**：`absorb(stkcdcode year)` 会把年份固定效应吸收掉，不会生成 `yr_2015`、`yr_2016` 等系数。因此 esttab 中 **不要写 `drop(yr_*)`**，否则会因找不到 yr_* 而报错。
* **只有手动生成年份虚拟变量（`tab year, gen(yr_)`）并用 `reg` 估计时**，才会产生 yr_* 系数，此时才需要 `drop(yr_*)`。
* **判断规则**：如果回归命令是 `reghdfe ... absorb(... year)`，esttab 不写 drop(yr_*)；如果回归命令是 `reg ... yr_*`，esttab 可以写 drop(yr_*)。

显著性标记建议：

```text
\* p < 0.10
\*\* p < 0.05
\*\*\* p < 0.01
```

表注示例：

```text
注：括号内为聚类稳健标准误；\*\*\*、\*\*、\* 分别表示在 1%、5% 和 10% 水平上显著。
```

## 18\. 代码规范

Claude 生成代码时应遵守以下规则：

1. 代码必须可运行。
2. 变量名应与数据中实际变量名保持一致。
3. 每段代码前添加简短注释。
4. 不写过度复杂的代码。
5. 不使用未经说明的外部包。
6. 不覆盖原始数据。
7. 输出路径应清楚。
8. 重要结果应保存到日志或表格文件。
9. 如果代码依赖特定软件版本，应说明。
10. 修改已有代码时，尽量最小改动。

注释风格示例：

```stata
\* 构造核心解释变量
gen digital\_index = ln(digital\_score + 1)

\* 基准回归
reghdfe risk digital\_index controls, absorb(firm\_id year) vce(cluster firm\_id)
```

## 19\. 论文结果写作模板

### 19.1 描述性统计写法

```text
表 X 报告了主要变量的描述性统计结果。被解释变量 Y 的均值为 X，标准差为 X，说明样本企业在该指标上存在一定差异。核心解释变量 X 的均值为 X，表明样本中企业在该方面的水平具有明显分布差异。整体来看，主要变量的取值范围处于合理区间，为后续回归分析提供了基础。
```

### 19.2 基准回归写法

```text
表 X 报告了核心解释变量 X 对被解释变量 Y 的基准回归结果。列（1）仅控制年份固定效应和个体固定效应，列（2）进一步加入控制变量。结果显示，X 的估计系数为正/负，并在 X% 水平上显著。这说明，在控制其他因素后，X 与 Y 之间存在显著相关关系。该结果与本文理论预期一致。
```

### 19.3 稳健性检验写法

```text
为检验基准结果的可靠性，本文从替换变量测度、调整样本范围和改变模型设定三个方面进行稳健性检验。结果显示，核心解释变量的系数方向与基准回归保持一致，且多数模型中仍具有统计显著性，说明本文主要结论具有较好的稳健性。
```

### 19.4 机制检验写法

```text
为进一步考察 X 影响 Y 的可能机制，本文引入机制变量 M 进行检验。结果显示，X 对 M 的影响显著，且在进一步控制 M 后，核心解释变量 X 的系数发生变化。这一结果支持了 X 可能通过 M 影响 Y 的机制解释。
```

### 19.5 异质性分析写法

```text
表 X 报告了不同分组样本下的回归结果。结果显示，X 对 Y 的影响主要集中在 A 组样本中，而在 B 组样本中相对较弱。这说明 X 的作用效果受到样本特征的影响，也表明本文结论存在一定边界条件。
```

## 20\. 结果解释边界

Claude 在解释实证结果时必须避免以下问题：

* 把相关关系写成因果关系。
* 把统计显著写成经济意义重大。
* 忽视不显著结果。
* 只挑选支持假设的结果。
* 过度解释控制变量。
* 忽略样本、变量和模型的限制。
* 在没有机制检验时强行解释作用机制。
* 在没有异质性检验时声称适用于所有情境。

## 23\. 禁止行为

Claude 不得执行以下行为：

* 虚构回归结果。
* 虚构数据来源。
* 虚构文献。
* 虚构显著性。
* 在没有结果的情况下编造结论。
* 不说明假设条件就直接给出确定判断。

* 删除用户已有代码中的关键逻辑。
* 用复杂语言掩盖研究问题不清楚。
