# 收尾归档验收与安全清理

目录和任务复用规则统一见[SKILL.md](../SKILL.md)。从当前 README 验证唯一工作根；同问题跨天跨对话复用原包，只读查询不建目录；只在原位置维护两张现用清单。

## 五类材料，两种判断

先确定用途类别，再确定现用状态；“必须保留”不能等同“所有都摆在现用目录”。

| 类别 | 必须保留的内容 | 日常位置/处理 |
|---|---|---|
| 原始数据 | 下载源表、原文、原始人工核对材料、来源和版本；只读，另备份 | raw或登记的共享源库，不为每次交付复制大数据 |
| 关键中间数据 | 清洗主表、身份匹配、人工修正、高成本文本评分、每列真实样本ID、系数/图表底表和.ster | 候选与现用数据均集中temp并登记状态；冻结历史final保留，现用只增列替换按核验门槛；记录重跑成本及不可重建部分 |
| 代码与运行记录 | 生成当前稿和全部约定事实的完整代码链、参数、依赖、种子、日志、输入输出清单 | 现用源码进do/code；采用前后日志和来源证据留原测试包；被替代正式源码入归档 |
| 正式结果 | 每次正式稿、图表、估计对象和设定，含不显著/负向结果 | 已采用且授权导出的排版表进result/table，图进result/figure；用户自行放稿件到初稿，AI文档留测试；估计对象进关键中间，被替代版进日期归档 |
| 临时文件 | 调试、可低成本重建的候选表、缓存、重复导出和测试解包副本 | 新增数据集中data/temp，非数据材料复用原测试包；审查后处理，不能仅凭tmp/old判断 |

状态固定使用：现用、已替代、待核验、隔离。缺少代码、源数据或人工修改来源的对象先标待核验，不列入可删。

## 控制现用代码数量的依据

现用主 do 必须保留；现用上游代码包括从原始材料到关键中间/最终样本的真实构建链，以及全部事实图表代码。并非只有被主程序直接调用的文件才有价值。

同一功能以一个明确现用实现为准。code现用脚本及必要配置按00_、01_、02_开头并写明用途；改名同步核对导入、动态加载、命令行、生成和打包筛选规则。正式历史实现、原路径快照、portable复制版、旧验收包装器、一次性搬迁/修复脚本移出日常code，集中到日期归档的来源代码区；不要另建几十个归档目录。归档前查清现用依赖；仍需读取的历史文件保留原字节，并将对应配置或调用指向归档位置，不能中断现用链路。

小文件可SHA256核对完全重复；哈希相同也需确认哪个路径被引用。近似文件须比较参数和研究口径，不能只凭文件名判为重复。历史正式版本不因不显著或被替代而销毁。

## 本次运行和正式交付

同一授权修改任务内，源代码首次编辑前备份一次原字节；连续微调复用该基线。正式发布版本替换仍归档；历史真实日志和核验记录不改写、不静默删除。任务说明更新当前有效正文，不累计重复补充。既有上游混合源包登记后可保留内部布局，迁移须同步当前路径与入口，不为排版规范拆散或复制。

候选与现用的小型数据、面板、样本ID、底表、估计对象和缓存统一在data/temp；代码、日志和导出物复用原测试包。只有用户明确采用后提取必要版本：复用现有数据，Python进code、Stata进do、获授权排版表进table、图进figure。最终分析用数据默认temp，另存final需明确冻结要求，原包完整保留。初稿只读，具体稿件编辑才按授权范围写入。

结束时核验候选，但仅用户明确采用后才识别相应入库范围。将要被替代的正式版本集中留一份日期版本归档；共享大数据以真实路径/版本/指纹引用，必要小型代码、设定和结果保存快照。提取用户明确采用且已核验的必要材料到现用位置并更新README与两张清单。不要每一轮都创建新的“定稿vXX”工作目录，也不要默认保留压缩包及其两套解包副本。

验证只恢复本次确需的材料：代码与证据进入原测试包，数据只读引用既有位置，确需独立恢复的数据集中data/temp并登记；不默认恢复整套副本。历史副本可归档的前提是现用复现不依赖其永久解包；若仍依赖，先报告该依赖并保留，不为了目录好看强移。

## 两张清单

下列路径是格式示例；已有项目必须复用 README 已链接的准确位置，不把日期替换成今天另建清单或管理包。

`测试/分析类别/YYYYMMDD_文件管理/文件清单.csv` 推荐字段：

```text
path,category,status,purpose,version,input_paths,producer,consumer_paths,rebuildable,rerun_cost,retention,sha256
```

category使用上述五类；路径相对ROOT，外部源路径保留绝对地址。能否重建和成本写具体依据（如“可由A+B重建，约8小时”“人工修正无备份，不能重建”），未知写未知。巨量分片按目录/批次登记，避免每次生成几万行重复清单。删除候选另列实际每个文件/目录、原路径、批准范围、隔离状态、下一次验收和释放空间。

`测试/分析类别/YYYYMMDD_文件管理/图表对应.csv` 推荐字段：

```text
manuscript_version,item_id,column_model,entry,input_paths,result_data,model_object,sample_ids,specification,output_paths,validation
```

每个正式表的每列模型登记一行；描述统计/手工文字表按实际来源登记。全部约定保留的特征化事实逐图逐表登记，即使当前主文没有全部使用。缺少两张图的代码就明确缺口并询问用户，不能推断代码已保留。

`specification`记录Y/X、控制变量时点、筛选、FE、聚类、权重和随机种子（适用时）；环境版本写在CLAUDE，参数/Prompt变动保留版本。不得只记录Excel结果路径。

## 每列模型的真实样本

在实际估计完成后、重新排序/替换数据或下一次估计前，立即用估计器真实样本保存ID。键按观测单位确定，不能默认每个项目都是企业年份。日常估计在 Python 中保存逐模型样本 ID；最终 do 里只按 stata-do-my-style 写 `gen sample=1 if e(sample)==1`，核对时用 log 中的 N 与 Python 样本 ID 比对，不在 do 里写 frame/program 保存样本。

各列分别保存或将带模型ID的样本集合存成长表，并核对观测数及唯一性。筛选标记、共同面板和N不是实际估计样本；reghdfe单例剔除等可能造成差异。估计器不提供e(sample)时按其接口取实际使用行并说明，不能造一个“看起来N相同”的样本。历史缺失样本ID时明确记未补齐；需要真实重跑才能补齐，不以文件结构PASS掩盖缺口。

`.ster`保存估计对象，支持恢复系数、lincom、导表等，但不能单独代替输入数据、设定及实际样本ID。候选与采用模型对象均集中data/temp并分别登记状态，采用时不重复复制；历史对象随正式版归档。新检验可能依赖评分/匹配底座，即使定稿回归只需小面板也要保留高成本上游。

## 清理前只检查三件事

1. 正式结果能追溯到输入、代码、设定和实际样本；全部约定事实图表无遗漏。
2. 现用代码、上游重建及约定新检验是否仍引用候选；包括运行时拼接路径、外部命令和人工材料，不只做一次静态字符串搜索。
3. 归档/备份能实际打开，恢复后的文件完整、关键指纹一致；仅压缩命令退出为0不算备份验收。

提供明确可审查清单，再执行已批准范围。候选先移至隔离区，记录原路径和指纹；确认下一次相应复现不受影响后，在用户授权范围内永久删除。批准只针对当前范围；“未经我确认，不删除已有文件”是默认规则，已经明确批准的同一清单不要反复询问。

缓存/spill需核实对应进程不再使用；完成标记可能过期，不能据此强制清空，更不能停止用户应用以便删除。确认合并完整的分片也要核实完整性和下游需要。没有源数据/备份的唯一评分、人工修正和原始文件不进入自动清理清单。

## 验收与报告

将结构、估计层面重跑、逐图重跑、全量原始重建分开报告；未跑写未跑。真实日志包含错误、实际样本数、模型设定和退出状态；保留全部正式结果，不用显著性筛选归档内容。

在原任务说明内更新本次范围、改动、前后映射、检查结果及遗留问题；只读检查不另造报告，真实新运行日志按逐表文件名加运行 ID 保留。不再增建独立“建议v01/核验v02/复现说明v03”目录。文件数减少和实际释放磁盘空间分别报告；硬链接、ZIP、隔离区和跨卷移动不能用逻辑大小直接推算释放量。

以后交给AI的固定要求：

> 初稿由我放自己写的论文，AI默认只读。同一研究问题跨天跨对话复用原包，新增数据、底表与对象集中data/temp，代码、日志和文档留原包；只读查询不建目录；共享大库只读引用。只有我明确结果或某项可以用了，才按范围提取必要版本：数据到data/temp、Python到code、Stata.do到do、排版表到table、图到figure，原测试包保留。按实际样本保存ID，未经我确认不删除已有文件。

最终 do 按 stata-do-my-style：一个项目一个主 do，从原始数据导入写起；每个分析小节以 `cd $DT` + `use 面板,clear` 开头，运行文件头路径段后可单独运行。不用preserve/restore，数据切换明确save/use；不写program助手。
