# 实证项目初始化与文件管理

## 0 优先级与适用边界

- **规则优先级：** 用户本轮明确指示 > 项目 README、CLAUDE 与实际设置 > 本 skill > references 与 templates。模板示例不能覆盖已确认的研究设定。
- **分工：** 本 skill 管目录、入口、清单、do 结构、迁移、归档和清理；计算、结果汇报和导出按 empirical-research。下文“共享规则”与该 skill 的同名一节保持一致，修改时两边同步。
- **整理不改研究口径：** 不改变 Y、处理变量、样本、控制变量时点、FE、聚类、阈值、种子或结果解释；初始化和整理也不授权运行新实证、重估或导出。

## 1 执行前确定范围

1. 读取用户给定路径、项目 CLAUDE.md/AGENTS.md、当前论文或手册、运行入口及最新日志，先确认研究对象和现用版本。
2. 选定范围：**初始化**、**已有项目归整**或**收尾归档验收**。沿用本会话已确认的路径、定稿和授权，不重复询问；只补问影响执行的缺失信息。
3. 先说明假设和简短验证计划。用户只要求理解、建议或审核时保持只读；要求执行时完成已授权的整理；删除已有文件须有针对准确清单的明确授权。

## 2 固定目录结构

完整说明见 [references/directory-structure.md](references/directory-structure.md)。只创建实际需要的目录。

```text
项目/
  README.md                         # 唯一现用入口
  CLAUDE.md                         # 研究设定、环境和数据流水线
  CLAUDE_empirical_analysis.md      # 通用实证规则，按需复制
  data/raw/                         # 外部原始数据，只读
  data/temp/                        # 候选/现用面板、共享缓存、样本ID、底表、估计对象
  data/final/                       # 现用最终面板及明确冻结版本
  do/                               # 平铺：现用 .do，可选一个 README.md 逐表入口
  code/                             # 平铺：现用 Python/R 代码和必要配置，两位序号开头
  result/table/                     # 用户采用且授权导出的排版表
  result/figure/                    # 用户采用的当前最终图
  paper/                            # 参考文献，有内容才建
  完整实证/                         # 授权生成的完整结果 Word 阅读副本
  初稿/                             # 作者论文，AI 只读
  测试/分析类别/YYYYMMDD_主题/        # 任务包：数据引用清单、代码、日志、回执、候选表图
  测试/分析类别/YYYYMMDD_文件管理/    # 唯一文件管理包：文件清单.csv、图表对应.csv
  投稿/                             # 当前投稿材料，按需
  归档/YYYYMMDD_正式vNN/            # 被替代的正式版本及必要历史证据
  YYYYMMDD_待删除/                  # 经确认的隔离区，按需
```

- `data/` 直接子目录只有 raw、temp、final，只放数据；不凭后缀、temp 位置或“最终面板”名称推定采用状态。
- `result/` 只放已采用且获授权导出的排版表图；CSV 底表与估计对象留 data/temp。完整汇编及未采用表图留测试包。
- 不新增 output、data/input、rules、reports、多套导航、空 do 或整套验收副本。没有“同类文件超过 N 个必须删”“代码最多 N 个”之类数量上限，以必要依赖和唯一现用职责为准。

## 3 初始化流程

### 3.1 盘点资源，锁定研究设定

- 路径已给出就核实，不再询问。读实证手册提取：研究主题、Y/X 构造与来源、控制变量、样本/面板个体、年份、FE、聚类、机制/异质性/稳健性清单及预期方向。无手册时从对话收集；缺失参数标“待确认”，不猜成可运行模型。
- 构造或合并前先查已有数据资产的字段、键类型、覆盖年份。用户本机的共享数据库（如 `F:/数据`）和上市公司控制变量路径以项目现有记录为准，先核实磁盘与文件可用，不沿用历史“送修/不可用”状态；不把上市公司金融/ST 筛选套到其他研究对象。
- 爬虫/LLM 数据：复用已登记的数据字典和验证清单；没有时在原任务包建一份，记录来源时间、覆盖与缺失、抽样人工比对、Prompt/模型/参数、误差与局限。阈值沿用项目约定，新阈值须有研究对象依据。

### 3.2 创建目录与项目说明

- 读取 [templates/README.md](templates/README.md)、[templates/CLAUDE.md](templates/CLAUDE.md) 后生成；已有文件按 S6 留一次原字节，更新相关原段，不整份覆盖用户内容。
- 项目 CLAUDE.md 是协作契约不是知识库，控制在约 2000–3000 tokens；变量、模型、检验清单都写在它的 §2–§3.1（原 rules/ 模板已并入）。
- 通用实证规则按需复制 [templates/CLAUDE_empirical_analysis.md](templates/CLAUDE_empirical_analysis.md)；文献卡片用 [templates/paper-card.md](templates/paper-card.md)，存 `paper/`。
- README 只回答：当前权威稿是哪份、论文表怎么跑、特征化事实怎么跑、已采用表图在哪、上游重建与环境要求在哪；并用真实本地 Markdown 链接指向文件管理包里的两张清单。代码/数据流水线写进 CLAUDE.md；明细放清单，不建多份“入口/导航v02”。

### 3.3 逐表 do 结构（仅研究版本确认或用户明确要求 Stata/do 时生成）

触发条件见 S7，写法与验收见 S8。

```text
00_导入原始数据与构建.do
01_统一设置.do
02_变量定义.do
03_描述性统计.do
04_逐步加入控制变量的基准回归.do
05_具体检验主题.do
……
主程序.do        # 可选，只按顺序调用，不占 00
```

- 文件序号是工作顺序，**不等于论文表号**；每个分析 do 在文件头和图表对应清单登记真实表号（DO_STEM 与 TABLE_ID 分别填写）。文件名为“两位序号_具体主题”，不能只写编号、T 编号、表4 或机制一。不得再生成 `00_统一设置`、`00_主程序`。
- 每张论文表一个现用 do，含该表全部列、真实样本记录、保存估计及获授权的导出段，同表模型不分散。改名同步主程序、生成/打包脚本及两张清单。
- **01 统一设置**集中：REPRO、ROOT、DATA、RAW、TEMP、FINAL、DO、CODE、RESULT、TABLE、FIGURE、LOGROOT、年份、控制变量 `$CONTROLS`、PANEL、面板键、FE、聚类、回归公共选项、统一标签、`ensure_dir`、`next_log`、`save_sample_ids` 等共用程序（01 开头 `program drop _all`，全程不用 capture）。01 不 use 数据、不回归、不清空数据、不重置种子；随机算法使用已约定种子并显式记录。
- **00 构建**先读 01，再从已登记来源导入，中间件写 TEMP；合成 DTA 集中 data/temp 并登记状态，另获冻结授权才写 final；PANEL 显式指向真实输入或未占用的新输出，不覆盖既有版本。00 模板中的 MAIN_INPUTS、KEY_VARIABLE_FORMULAS 按真实项目填写，删除不适用示例。
- **路径与阶段**：
  - `TASK_NAME_DATE`：原测试证据包名（继续、采用、重跑都沿用）。
  - `TASK_DATA_PATH`：data/temp 内已登记的真实数据位置，TEMP 指向它。
  - `TASK_STAGE`：trial 或 adopted，只控制 DO/CODE/RESULT/TABLE/FIGURE 指向测试包还是正式目录。
  - `LOGROOT`：任何阶段都指原测试包。
  - `PANEL_RELATIVE_PATH`：实际读取或新建的面板，不固定绑定 final。
  - 未采用但要求核对时，所有 do 和本轮 01 生成在同一测试包，把首个 `do` 语句改为该包内 01 的真实绝对路径，禁止加载正式目录旧设置；运行前逐项展开检查。
- `templates/do/05–09` 及相关系数模板按论文实际表数拆取。02 变量定义表若为人工文字须标明；由代码产生则配置 VARIABLE_DEFINITION_CODE_BLOCKS，不伪造结果。为 01 提供真实面板键、FE、聚类和控制列表；非 e(sample) 估计器按接口取真实行。存在未替换占位符或缺输入的文件标“未就绪”，不能报告可一键复现。

### 3.4 运行产物落位

- 未采用的新数据与缓存在 data/temp，程序、表图、日志、文档在分类测试包；采用后按 S5 提取。
- 重估、重导或替换正式面板前，为被替代正式版留可恢复归档，再更新现用材料并维护两张清单。
- 分别报告结构整理、独立 do 执行、估计对照、图表重跑的实际完成状态。

## 4 已有项目归整与收尾验收

执行 [references/file-management.md](references/file-management.md)，不先移动再找依赖。

1. **只读盘点**：现用稿、主程序、逐表逐图来源、高成本链路、外部共享输入、文件引用、正式历史版本和重复副本；记录旧路径与必要指纹。
2. **分类并给去向**：每项标为现用 / 已替代 / 待核验 / 隔离，不能笼统“全部保留”。现用代码保留全链路和必要辅助；历史来源、调试和包装脚本集中归档。
3. **最小改动执行**：首次修改的源码留一次原字节；迁移必要材料，同步 ROOT、绝对/相对路径、动态导入、do 调用、打包/生成器、README 与两张清单，不叠加路径包装器。迁移前核实源/目标解析后的绝对路径都在授权范围内，处理同名冲突。迁移记录用于回滚；新结论写入管理包当前说明。
4. **验收**：核对迁移前后映射、数量与指纹，初稿和图表原字节受保护；检查 README/清单链接、程序输入存在性、旧根残留和动态路径风险，把现用可执行引用与历史文本旧路径分开报告。按授权做必要的只读入口或语法检查，不因迁移重跑估计、绘图或大库。分别报告文件完整性、静态引用、实际入口检查、估计重跑、图表重跑、全量原始重建的真实状态；静态通过不能称全部可复现。
5. **清理**：按 S6 删除流程。原始数据、人工修正、全国评分等高成本数据及正式非显著结果，不得因 tmp/old/日期早而机械删除。同一清单已授权不反复确认，新候选需要新授权。
6. **交付**：只给一个当前入口，说明迁入、归档、隔离、永久删除各多少、保留什么、验收范围和未解决项。磁盘问题报告逻辑大小与实际释放空间，硬链接不重复计算。

## 5 两张现用清单

均放在唯一管理包 `测试/分析类别/YYYYMMDD_文件管理/`（包名即 `{{MANAGEMENT_TASK}}`），只在原位置更新，不为一次整理新建管理包。

- **文件清单.csv**：路径、用途类别、现用状态、版本、上游/下游、能否重建、重跑成本、保留建议、必要指纹。大规模分片可按目录/批次登记；待删清单必须逐项列实际对象。
- **图表对应.csv**：稿件版本、表/图号、列/模型、入口 do/图代码、输入、结果底表、模型对象、**实际样本 ID 文件**、设定、输出、验证状态。每列样本从实际 e(sample) 或估计器真实样本保存，不能从 N 或共同面板推测。
- `.ster` 是估计对象，不当缓存默认删除；保留与现用表及历史正式版本对应的对象，完全相同副本经引用核验后再处理。

## 6 验证与报告

- 生成后检查占位符、路径、逐表调用顺序和未就绪内容。
- 可运行 `scripts/check_project_layout.py 项目路径` 做只读结构检查：它检查初稿中的任务包/非稿件材料并提示需人工确认的项，不能判断 Word 作者、不能证明写入初稿已获授权、不验证实证结果、不删除文件。须保留相对布局的历史包用重复的 `--legacy-bundle data/raw/准确包名`、`data/temp/准确包名` 或 `code/准确模块包` 列出，不能排除整个 data/raw、data/temp 或 code。未使用的目录不必为通过检查而创建。
- 模板或资料缺失时保留已完成工作并报告具体缺口，不凭空声称复现。

## 共享规则（与 empirical-research 保持一致）

### S1 工作根与初稿

- 唯一工作根以 README、CLAUDE 和实际设置共同指向的真实路径为准，skill 不硬编码项目目录。已授权迁移时同步路径与入口，不重复索要同一授权。
- `初稿/` 是作者论文区，AI 只读；只有用户指定具体稿件及编辑范围时才操作。导出、确认结果、采用均不授权写初稿。读取参考 Word 时不在其旁边写任何文件。

### S2 任务包：先复用，后新建

- 位置：`测试/分析类别/YYYYMMDD_主题/`。“分析类别”是占位：先判断本任务内容属于哪一类，再放进该类别的文件夹（例如做异质性相关的任务就放 `测试/异质性分析/`）。七个固定类别：**特征化事实、异质性分析、机制、基准、稳健性检验、进一步分析、初稿整理**；不创建名为“分析类别”的文件夹，类别层不加日期，不新增第八类。
  - 特征化事实：描述性事实、趋势、地图、行业或资本分布及其图形调整。
  - 异质性分析：分组、交互项、行业及企业特征差异。
  - 机制：机制变量、渠道及该机制自身的样本、控制、聚类、平行趋势诊断（标题含“稳健”也不拆出）。
  - 基准：主分析面板、主 Y 与处理变量构建、基准估计及口径核查。
  - 稳健性检验：主结果的替代口径、缩尾、样本敏感性、识别与影响诊断。
  - 进一步分析：扩展问题、额外结果变量及补充调查。
  - 初稿整理：稿件文字与表格整理、政策背景、跨章节整套汇编、版本核查、目录/文件/skill 管理（AI 工作区，区别于根目录 `初稿/`）。
- 一个包只归一个主要类别；跨章节完整包整包放初稿整理，不按文件类型或表号拆散。无法判断时先读任务说明与输出对应关系，仍缺影响归属的信息才询问。
- 两张现用清单（文件清单.csv、图表对应.csv）只放唯一文件管理包 `测试/分析类别/YYYYMMDD_文件管理/`（包名即 `{{MANAGEMENT_TASK}}`），README 链接这一处，只在原位置更新。文件管理按类别定义（目录/文件/skill 管理）归入初稿整理，所以实际路径在 `测试/初稿整理/` 下。
- 同一研究问题的跨天/跨对话继续、表图微调、补统计量、同问题控制或参数诊断、核验、导出、采用、修复、重跑，**都沿用原包与原开始日期**。只读查询、解释、盘点不建包、不写回执。只有“新的独立研究问题 + 无可复用包”才新建。
- 每包一份任务说明（范围、状态、输入输出、检查）；新运行日志用运行 ID 命名；仅并行运行或大量中间文件需要隔离时才建包内运行子目录。
- 日志、诊断、核验回执、渲染预览、来源与采用记录始终留原测试包，采用不迁走；项目根不建 `logs/`。
- 分类本身不代表采用，不授权重估、导出或删除。

### S3 数据集中在 data

- `data/raw/`：外部原始来源，只读。`data/temp/`：构建数据、共享中间层、候选/现用分析面板、回归底表、估计对象、b/V、实际样本 ID、高成本缓存；任务专属数据可放 `data/temp/YYYYMMDD_主题/`。`data/final/`：现用最终面板和明确冻结的版本。目录位置不表示采用状态，状态在清单中登记。
- 同一可复用数据只保留一个现用物理副本，跨任务只读引用，不随测试包复制；测试包登记真实路径、版本、指纹、生成代码、状态与调用关系。共享大库只登记，不复制。“完整任务包”指完整可追溯链，不是复制全部数据。
- 去重依据 SHA256 或完整结构/数值核验；同名但样本、定义、参数或实际支持 ID 不同的文件不是重复。
- **现用面板只增列时可原位替换**，须全部满足：面板主键唯一且一对一对齐，键集合、行数、样本/年份范围相同；全部原有列逐项核验值、缺失状态、编码/类型、尺度及标签未变；只新增原面板没有的列。禁止覆盖同名列、增删行、改排序对应、只抽查部分旧列或用宽松容差。通过后在 data 内保留替换前原字节与哈希（如 `data/temp/YYYYMMDD_面板增列/原面板归档/`），先写暂存面板并回读核验再原子替换，登记新增列、匹配覆盖率、前后指纹、备份位置。任何旧列、主键或样本变化则另存候选，不替换。补列不使原结果失效，也不自动重估、采用新变量或导出。冻结历史版本只读。

### S4 命名

- **目录**：任务包、采用项、结果版本、归档一律 `YYYYMMDD_主题`，同日重名用 `YYYYMMDD_HHMMSS_主题`；禁止“主题_日期”。日期取任务实际开始日，继续沿用原日期，不以整理日替代；无可靠日期先查日志/来源，仍不明标“待确认”，不编造。建目录前列出完整目标路径核对，收尾再查一次。固定用途目录（data、raw、temp、final、do、code、result、table、figure、测试、归档、初稿、完整实证）及包内用途分类不加日期。
- **阅读与分享产物**：Word、PDF、RTF、Excel、PPT、可分享图片用 `YYYYMMDD_主题.扩展名`；单表/单图如 `20261010_表13_城市VC获投企业家数.docx`；Word 与配套 PDF 同主名；文档核验回执为 `<主名>.核验.json`。文件日期是该产物的生成/修订版本日，采用、迁移、归档不改写。同名更新先归档，不堆“最终版/修复版”。
- **其他文件**：现用代码以两位工作序号开头；机器底表、估计对象、样本 ID 按模型 ID 或阶段命名；渲染页图与缓存保留工具编号，放对应文档的核验目录；原始来源、作者稿件、历史日志/回执/测试输入保留原名。
- **改名/迁移**：先登记准确映射、检查重名和依赖，同步现用程序、导出器默认值、模板、README 与两张清单；历史日志和回执保留原字节，通过映射回查。

### S5 采用与入库

- 采用只来自用户明确表态（“这个结果可以用”“采用表13第2列”）。“挺显著”“看看”“继续做”、构建完成、导出成功、验收通过、文件名含“最终”都不是采用。
- 按范围提取最小完整复现链：数据复用 data/temp 中已登记的位置，不再复制；Python 源码与必要配置进 `code/`；`.do` 进 `do/`；已采用且获授权导出的排版表进 `result/table/`，图进 `result/figure/`。部分采用只提取指定模型及必要依赖。未采用的代码和表图不进现用目录。
- 采用不触发重估、改模型或扩展导出格式；单项采用不等于整个研究版本确认。
- 登记采用范围、源/目标、指纹、模型设定、实际样本和调用方式，更新清单；原测试包保留，其中显著/不显著/负向/失败状态继续可查。
- **`完整实证/` 阅读副本**：每次用户授权生成全部实证结果的完整 Word 汇编并完成核验后，另复制一份到 `完整实证/`（只放完整汇编 docx，不放单表、PDF、底表、脚本、回执）。它不表示采用。复制前同名同哈希则复用，内容不同先归档再复制，禁止静默覆盖；复制后核对 SHA256 并登记源/目标与版本。汇编单独登记所含各表版本及尚未合并的采用项；单表更新后，旧汇编及其副本不能称为最新版。此规则不触发生成。

### S6 最小留痕、备份与清理

- 同一授权修改任务内，每个源文件首次编辑前保存一次原字节与哈希，后续微调复用该基线。被替代的正式结果、数据与代码版本留可恢复归档（`归档/YYYYMMDD_正式vNN/`）。
- 真实运行日志、已出具回执和冻结证据不改写、不静默删除；修正写进当前说明并引用旧记录。
- 核验只生成必要材料：复用仍匹配当前文件的已有证据；图形微调只看论文尺寸最终输出；文档导出按受影响内容检查；不机械生成整套验收副本、拼图、解包或额外格式。渲染放原包既有预览位置，历史证据不覆盖。
- 删除已有文件：准确清单 → 用户确认 → 隔离到 `YYYYMMDD_待删除/` → 相应复现通过 → 删除。任何规则都不自动清理历史文件。
- 修改 README、CLAUDE、skill 或模板时改原段并消除冲突，一条规则只保留一个权威定义，不在文件头追加“最新补充”；必要的历史规则作一次原件快照。
- 历史混合源包和仍被调用的上游代码模块登记后可保留内部相对布局，不为平铺而拆散，也不复制第二套；不得把新日志、图表写进代码/数据区。

### S7 计算、展示与导出的授权边界

- 日常计算与结果交付只用 Python。只有用户确认**整个研究版本**（“确定用这一版”“研究设定已经定了”或同义）后，才冻结输入与设定并生成/执行最终 do 核对；用户直接要求 Stata/do 核对时按其范围执行。“重新跑所有结果”“导出这个表格”“生成最终面板”、路径含“定稿/最终版”、旧版本曾被采用，都不是版本确认。
- 结果跑完先在对话总结；只有用户明确要求才生成 Word、PDF、RTF 等排版文档。最终版本确认、生成 do、Stata 核对都不自动授权导表。

### S8 最终 do 写作与验收（仅核对阶段适用）

- **参考表头**：每份 do 在首个书签和命令前用 `/* ... */` 写 `project`、`Author`、`E-email`、`Creation Date`、`Modification Date`、`Do-file version`、`References`、`Input`、`Output`；输入输出写本文件实际依赖与产物；未知项写“未记录”，不抄示例个人信息，不把磁盘时间当原始创建日期；改动后更新修改日期，并区分文档整理与估计口径变化。
- **阅读路线**：表头后写目的、必要输入、主要步骤、关键公式与单位、样本限制、关键输出和单独运行方法。
- **原生书签**：每个实际工作部分前独占一行 `**# 01 中文小标题`，长文件用 `**# 04.1 合并某来源` 区分来源、模型组或表；单文件内编号唯一并按执行顺序递增；`* === [书签]` 等普通注释不算。
- **口径可追踪**：计算旁写公式、单位、时点、缺失处理和样本限制；合并旁写来源文件、键、未匹配处理；多来源补值写明优先级。关键口径不藏进通用循环、动态生成代码或另一门语言。路径与共用控制取自统一设置。
- **独立运行**：每个分析 do 先用绝对路径 `do` 读取 `01_统一设置.do`，再显式 `use`/`import` 自己的输入；不依赖主程序残留的数据、宏、frame、postfile 句柄、program 或估计对象；自开自关日志和 postfile。
- **禁用 preserve/restore**：数据切换写成 `save "$TEMP/阶段数据.dta"` + `use`。允许 `estimates store/save/restore`，估计对象存 TEMP。e(sample) 由 01 中的共用程序 `frame put` 真实键 → 存 TEMP → drop frame。program 内用全局 `$TEMP`，避免外层 local 展开为空把文件写到磁盘根。
- 通用辅助程序只在 01 实现一次；表专用交互、分组、筛选与差异检验留在对应 do。统一控制变量必须在 01 中有可执行的 `global CONTROLS 真实变量列表`，全项目用 `$CONTROLS` 引用；do 中不使用 capture，目录、日志与文件检查用 01 的 `ensure_dir`、`next_log` 和 mata，FE、聚类、标签、PANEL、辅助程序逐项核对。
- 不得用历史生成脚本或快照覆盖整改后的现用 do；改名同步调用、导航和图表对应清单，旧入口归档保留原字节。
- RTF 等导出段默认注释，只有用户授权相应表与格式后才启用。
- 特征化事实不生成 do；do 只含构建、设置、变量定义、描述统计、回归与识别图、结果提取。
- **验收**：新开 Stata 会话单独运行某表 do；逐项报告已改、实际运行通过、尚未验证的范围。只改注释时逐行核对可执行命令不变；静态检查、字节检查不能称为复现，发现遗漏不能沿用上轮“已完成”。可读性测试：不依赖本次对话的读者能答出 Y 怎么算、控制变量是什么、样本怎样筛、最终读哪份 DTA。

### S9 默认研究设定（项目另有要求或用户说明时以其为准）

- **基准回归默认四列**：(1) 无控制无FE (2) 有控制无FE (3) 无控制有FE (4) 有控制有FE（首选）；不同项目的列数以稿件和项目 CLAUDE.md 为准。
- **统一样本**：各列及后续机制、稳健、异质和描述性统计默认使用同一 `_sample == 1`（第 4 列所需全部变量非缺失）；偏离由用户说明，并在表注和图表对应清单登记。Python 估计同样以此为默认样本，并照常保存每个模型的真实样本 ID。
- **机制检验默认一步法**：只估计 X 对当期机制变量 M 的影响；不把 M 放进基准回归，不做第二步，除非项目另有要求。
- **控制变量宏**统一为 `global CONTROLS`，全项目引用 `$CONTROLS`。
- **Stata do 不使用 capture**；目录、日志、文件检查用 01 的助手。
- **回归表保留常数项和控制变量系数**：esttab 不用 `keep()`、`drop(_cons)`。
- **样本删除可追溯**：raw 只读；构建面板时可以 drop，但每步前后记录 N 与删除数，登记到项目 CLAUDE.md 的样本筛选表。
- **不导出 LaTeX**；排版文档按 S7 只在用户明确要求时生成 Word/PDF/RTF。
