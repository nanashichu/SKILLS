# 实证项目初始化与文件管理



## 执行前确定范围



1. 读取用户给定路径、项目现有 CLAUDE.md/AGENTS.md、当前论文或手册、运行入口及最新日志。先确认研究对象和现用版本，再讨论文件。

2. 选择本次范围：**初始化**、**已有项目归整**或**收尾归档验收**。沿用本会话已确认的路径、定稿和授权，不重复询问；只补问影响执行的缺失信息。

3. 先说明假设和简短验证计划。用户只要求理解、建议或审核时保持只读。用户要求执行时完成已授权的整理；删除已有文件须有针对清单的明确授权。

4. 整理目录不能改变 Y、处理变量、样本、控制变量时点、固定效应、聚类、阈值、种子或结果解释。已有项目以用户确认的研究设定为准，模板中的示例不能覆盖它。

5. **结果展示与文档导出分开（2026-10-10用户更新）。** 实证结果跑完先在对话总结显著组合、方向和幅度、合理设定的依据、不显著/反向/失败与关键诊断、下一步建议；只列必要代表规格，完整底表给路径，用户要求时再展开；数据、完整估计、系数底表、样本ID、代码、日志及核验回执照常保存。只有用户明确要求导出时才生成Word、PDF、RTF等排版文档；目录结构中的初稿、投稿和result位置不构成自动导出授权。已明确要求导出的格式按本轮范围直接执行，不重复询问，不擅自增加交付格式或重跑回归。


## 工作根、任务复用与最小留痕

- **唯一工作根以当前项目为准。** 读取项目 README、CLAUDE 和实际设置，确认它们指向同一个真实工作根；通用 skill 不硬编码任何项目的旧目录。用户已授权提升或迁移工程时，同步更新路径与入口，不重复索要同一授权；删除已有文件仍须另按准确清单授权。
- **先查已有包，再决定是否新建。** 同一研究问题跨天、跨对话继续，图表字体/图例微调、补统计量、同问题控制或参数诊断、核验与导出，都沿用原任务包和原开始日期。只读查结果、解释、盘点不创建目录或回执。只有新的独立研究问题且没有可复用包时，才按七类创建一个日期前置包；日期变化、新对话、采用、修复、重跑或“单独留记录”本身都不是新建理由。
- **固定清单与过程记录。** README 只链接一处现用文件清单和一处图表对应清单；继续任务更新既有行，文件管理工作沿用原管理包。每包用一份任务说明汇总范围、状态、输入输出和检查，必要新运行日志采用运行 ID 文件名；仅有并行运行或大量中间文件隔离需要时才建包内运行子目录。只读复查不为证明自己查过再造报告。
- **备份按授权任务与正式发布边界。** 同一授权修改任务内，每个源代码文件在第一次编辑前保存一次原字节和哈希；后续微调复用该基线，不逐轮备份。被替代的正式发布结果、数据与代码版本仍须留可恢复归档，不以此规则覆盖未获授权的历史版本。真实运行日志、已出具回执和冻结证据不改写、不静默删除；修正写进当前说明并引用旧记录。
- **核验只生成必要材料。** 先利用已有且仍匹配当前文件的证据；内容变化使旧证据失效时才做对应检查。图形微调查看该图在论文尺寸的最终输出；文档导出按受影响内容做数值、结构及视觉检查，不机械生成全套验收副本、拼图、解包、独立 PDF 或多格式交付。渲染进入原包既有预览位置，已留存历史证据不静默覆盖。
- **规则只保留当前有效正文。** 修改 README、CLAUDE、skill 或模板时，更新相关原段并消除冲突，同一规则保留一个权威定义；不要不断在文件头追加“最新补充”并把相反旧句留在正文。必要历史规则作为一次原件快照保留。
- **已有上游包保留必要结构。** 历史混合源包及仍被调用的上游代码模块可登记后保留内部相对布局；含模块导入或 vendor 依赖的现用代码包不因平铺约定拆散。登记准确包路径及依赖，禁止借此新增一套重复上游或把新日志、图表任意写入代码/数据区。

## 数据集中存放与面板增列替换

**数据统一放data，测试包按类别保存任务记录。** `data/raw/`只读保存外部原始来源；`data/temp/`集中保存构建数据、共享中间层、候选/现用分析面板、回归底表、估计对象、协方差、实际样本ID与高成本缓存；`data/final/`保存现用最终面板和明确冻结版本。候选数据也可进temp，目录位置不表示采用。同一可复用数据只保留一个现用物理副本，跨对话和跨检验只读引用，不随测试包复制。任务专属新数据可用`data/temp/YYYYMMDD_主题/`；在测试包登记真实路径、版本、指纹、生成代码、状态与调用关系。

`测试/类别/YYYYMMDD_主题/`保存代码、配置、日志、说明、来源/核验/采用回执、候选表图、获授权文档及渲染；数据实体引用data中的位置。“完整任务包”指完整可追溯链，不要求把全部数据复制进包。不要把不同样本、不同变量定义、不同参数或不同实际支持ID的文件按同名误判为重复；去重依据SHA256或完整结构/数值核验，迁移前查依赖并更新现用引用，历史回执保留原字节。已有重复文件的删除仍须准确清单及确认；本规则不自动清理历史文件。

**只增加新列且原面板完全一致时，允许直接更新原现用面板。** 先以面板主键一对一对齐，确认主键唯一、集合与行数相同、样本/年份范围相同；全部原有列逐项核验值、缺失状态、编码/类型、尺度及标签等必要元数据均未改变。只新增原面板不存在的列才通过；禁止覆盖同名旧列、删行、补行、扩大或缩小样本、改变排序对应关系，禁止仅抽查部分旧列或用宽松容差掩盖修改。

通过后在同一data体系保留可恢复的替换前原字节及哈希（例如`data/temp/YYYYMMDD_面板增列/原面板归档/`），先写暂存新面板并回读核验，再原子替换现用路径，登记新增列、匹配覆盖/新列缺失、前后指纹、备份位置与现用清单。其他旧列或主键/样本改变时另存独立候选，沿用原有采用/冻结授权，不替换主面板。若只是补新列，原有回归结果不因此自动失效，也不自动重估、采用新变量或导出文档。冻结历史版本继续只读；明确标记为现用的最终面板可按上述增列门槛更新。

Stata核对阶段：`TASK_DATA_PATH`指data/temp中的真实数据任务；`TASK_STAGE`填写trial或adopted，仅控制代码/表图路径。未采用的do、CODE、RESULT、TABLE、FIGURE均指分类测试包；采用后按原用途提取。LOGROOT在任何阶段仍指原分类测试包。数据位置和结果采用状态分别登记，不能从temp路径推定已采用。

## 测试目录按分析类别分组

测试任务包统一放在`测试/分析类别/YYYYMMDD_主题/`。分析类别只使用七个固定名称：**特征化事实、异质性分析、机制、基准、稳健性检验、进一步分析、初稿整理**；“分析类别”是占位说明，不创建同名文件夹。类别层不加日期，任务包保留真实开始日期。先从现用清单和研究问题定位原任务包；同一研究问题始终沿用原类别与原包。只有新的独立研究问题且无可复用包时才新建；只读查询不建包。

- 特征化事实：描述性事实、趋势、地图、行业或资本分布，以及相关图形调整。
- 异质性分析：分组、交互项、行业及企业特征差异。
- 机制：机制变量、司法与融资渠道、微观创新机制及该机制自身的样本、控制和聚类诊断。分类依据主要研究问题，不因标题含“稳健/平行趋势”就拆散机制包。
- 基准：主分析面板、主Y与处理变量构建、基准估计及其口径核查。
- 稳健性检验：主结果的替代口径、缩尾、样本敏感性、识别与影响诊断。
- 进一步分析：扩展问题、额外结果变量及补充调查，例如创业意愿。
- 初稿整理：稿件文字与表格整理、政策背景、跨章节整套汇编、版本核查、目录/文件/skill管理。`测试/初稿整理/`是AI工作区；项目根`初稿/`仍由用户放自己的论文，AI默认只读。

一个任务包只归一个主要类别。现有跨章节完整包整包放初稿整理，保留包内数据、代码、日志、回执与产物，不按文件类型或表号拆散；单项机制或异质性导表仍归相应分析类别。确实无法判断归属时先读取任务说明、研究问题及输出对应关系；只有影响归属的缺失信息才询问，不新增第八类。

`TASK_CATEGORY`填写上述真实类别；`TASK_NAME_DATE`仍仅填写日期前置的包名。`TASK_DATA_PATH`在各阶段都指`data/temp/YYYYMMDD_数据主题`的真实数据位置，另行登记候选/采用状态；`LOGROOT`始终指原分类测试包。唯一现用文件管理包位于`测试/初稿整理/{{MANAGEMENT_TASK}}/`，同步README的真实链接与两张现用清单。

迁移旧任务先登记准确源/目标、重名与依赖，再保留整包并核对文件指纹；同步现用程序、配置与导航。历史日志、回执、冻结输入及作者稿件保留原字节，旧路径通过准确映射回查。分类本身不表示采用结果，不授权重估、导出或删除文件。

## 试验包与采用入库（2026-10-10用户最新约定）

**完整实证Word阅读副本（2026-10-10用户最新约定）。** 项目根新增固定用途目录`完整实证/`。以后每次用户已授权生成全部实证结果的完整Word汇编，完成该阶段核验后在这里另外放一份，沿用`YYYYMMDD_主题.docx`文件名；这一阅读副本不以作者采用结果为前提，也不表示结果已被采用。原Word、代码、数据引用、日志、核验回执和渲染仍保留原测试包；完整实证只放完整汇编Word，不放单表、PDF、底表、脚本、回执和缓存。复制前核对目标，已有同名且同哈希时复用，内容不同先保留可恢复归档，禁止静默覆盖；复制后核对SHA256并登记源/目标、版本与未同步项。完整实证是固定目录，不加日期前缀；单表仍按既有采用规则进入result/table，初稿仍由作者放论文。此约定不自动触发Word生成、重估或合并新版表。

**完整汇编单独登记版本。** 某张表被新结果替换后，旧汇编及完整实证中的阅读副本仍是原版本，不能因复制、改名或单表采用称为最新版；现用清单记录汇编所含表版本和尚未合并的采用项。

**生成的阅读与分享产物也日期在前（2026-10-10用户确认）。** 新生成的Word、PDF、RTF、Excel、PPT和可直接查看/分享的图片使用`YYYYMMDD_主题.扩展名`，同日确需并存不同独立版本时加时间。单表/单图在日期后写表图号和主题，例如`20261010_表13_城市VC获投企业家数.docx`。Word与配套PDF主文件名一致，文档专属核验回执沿用主文件名，例如`20261010_表13_城市VC获投企业家数.核验.json`。目录日期记录任务开始，文件日期记录本产物的生成/修订版本；版本日期有可靠依据才填写，采用、迁移或归档不重写原版本日期。新产物命名必须同步导出器默认值、模板、实际引用和现用清单；同名更新先归档，不堆“最终版/修复版”副本。现用代码按工作序号，机器底表/估计对象/样本ID按模型ID或阶段命名，渲染页图及缓存保留工具编号并放对应文档的核验目录；原始来源文件、作者稿件和历史日志/回执/测试输入保留来源名称，不能为了命名改写冻结证据。初稿和采用入库的边界不因命名改变。

**建目录前先核对命名。** 新任务、采用项、结果版本和归档包先列出完整目标路径，确认目录名以真实的8位日期开头；禁止生成“主题_日期”形式。`TASK_NAME_DATE`和`MANAGEMENT_TASK`都填`YYYYMMDD_主题`形式的完整包名；已有目录改名后，同步这两个占位符及所有实际路径。收尾再检查本次新建目录，发现日期在后就修正并核验引用。

**目录日期统一在前（2026-10-10用户约定）。** 任务、采用项、结果版本和归档目录用`YYYYMMDD_主题`，例如`测试/机制/20261010_VC新口径`、`data/temp/20261010_VC获投企业家数_采用`；同日独立任务重名时用`YYYYMMDD_HHMMSS_主题`。日期取任务实际开始日，继续原尝试沿用原日期，不能以整理日替代历史任务日期；没有可靠日期时先查日志/来源，仍不明则标为待确认，不编造日期。data、raw、temp、final、do、code、result、table、figure、测试、归档、初稿、完整实证等固定用途目录及数据/程序等包内分类保持用途名称，不强加日期。文件名继续遵循各自规则，现用代码仍按两位序号开头。旧目录改名先登记准确映射、检查重名和依赖，同步现用程序、README和两张清单，核验原文件；历史日志与回执保留原字节，通过路径映射回查。

**日志与追溯统一留测试包。** 项目根不新建或保留`logs/`。采用前后，运行日志、诊断、核验回执、渲染预览、来源和采用记录始终留在原`测试/分析类别/YYYYMMDD_主题/`；采用不迁走证据。对采用项获授权重跑时沿用原包，以运行 ID 区分真实日志；仅并行或大量文件需要隔离时建包内运行子目录，先保留被替代记录。LOGROOT只指该包或其子目录。项目两张现用清单放一个明确的文件管理测试包，README用真实本地Markdown链接指向文件清单.csv和图表对应.csv，不为每次尝试复制导航。迁移历史logs先查依赖、记录映射与指纹，同步现用引用；保留原字节，删除仍须明确授权。

`初稿/`由用户放自己写的论文，AI默认只读；只有用户明确指定某稿件及编辑范围时才操作该文件。导出文档、确认结果或采用版本均不授权写入初稿。

- **先确认工作根，再确定任务。** 从现用README、CLAUDE及设置确认研究工作根，不能直接把对话cwd当作输出根。已有项目沿用经当前 README 和设置实查的唯一工作根；迁移后按更新的真实根继续，不从旧 skill 示例恢复旧目录。
- **一个独立研究问题对应一个长期复用的任务包。** 依“工作根、任务复用与最小留痕”先查原包；同问题的字体微调、控制或参数变化用原包内文件或规格 ID 记录。只有独立问题无原包才创建`测试/分析类别/YYYYMMDD_主题/`，同日独立问题重名才加时间；不以对话或修订轮次建包。
- **未采用前，代码、日志、核验和候选产物留分类测试包，数据集中在data/temp；完整汇编Word另存完整实证阅读副本。** 小型来源快照、候选面板、DTA、CSV/Parquet底表、完整b/V、估计对象、样本ID及数据缓存放data/temp，登记候选状态；脚本、配置、日志、说明、回执、候选表图、Word和渲染留分类测试包，尚未采用的代码和表图不提取到现用code/do或result。构建完成、数值显著、导出成功、验收通过及文件名含“最终”均不是采用许可。
- **共享大库和已有冻结输入只读引用。** 记录真实路径、版本和必要指纹，不复制整个底座；必要的小型来源快照也集中在data，测试包登记指纹和引用；新增高成本数据放data/temp并登记所属任务，后续引用原件。
- **采用必须来自用户明确表态，并按范围提取。** “这个结果可以用”“采用表13第2列”允许对应结果入库；“挺显著”“看看”“继续做”不允许。部分采用只提取指定模型及必要依赖，其他口径、失败与未采用结果继续留原测试包。
- **采用后的必要版本按用途保存。** 分析面板、变量数据、底表、实际样本ID、完整b/V和估计对象复用data/temp中已登记的数据位置，不因采用再复制；Python源码及必要配置进`code/`；Stata `.do`进`do/`；已采用且获授权导出的排版表格进`result/table/`，图进`result/figure/`。只保存所选结果的最小完整复现链，不把整个测试包塞进data。采用后的分析用最终数据也默认进data/temp；冻结历史data/final只读保留；现用面板可按只增列门槛替换；其他另存final仍需明确冻结要求。
- **采用不等于运行新计算。** 入库读取已有核验结果，不因采用自动重估、改变模型或扩展导出格式。单项采用不等于整个研究版本确认；最终核对do生成/执行仍依后端规则，只在整体研究版本确认或明确要求Stata/do时开展。已存在且属于选中结果的do可按授权范围入库。
- **原测试包完整保留。** 采用时复用集中数据并提取现用代码，保留原任务记录，登记用户采用范围、源/目标、指纹、模型设定和实际样本，以及调用方式；正式清单更新相应采用项。包内各项的显著/不显著/负向/失败状态继续可查。
- **执行前检查全部真实输出。** 包括旧程序默认路径、相对路径基准、旁路回执、缓存和渲染。读取参考Word不允许向其旁边写入；日志、核验和渲染无论是否采用都须先把旧输出改到原测试包。源代码按同一授权任务首次修改保留一次基线；替换正式版本仍保留可恢复归档。清理仍按准确清单、用户确认、隔离、验证后删除。历史旧目录约定不能覆盖本节；在用户已授权的迁移范围内执行，其他历史材料不自行搬动。

## 初始化流程



### 1. 盘点已有资源，锁定研究设定



路径已给出就核实，不再次询问。新项目读取实证手册并提取研究主题、Y/X 构造与来源、控制变量、样本/面板个体、年份、FE、聚类、机制/异质性/稳健性清单及预期方向。没有手册时，从本次对话收集；缺失参数标为待确认，不能猜测成可运行模型。



构造变量或合并前先查已有数据资产及字段、键类型、覆盖年份。可检查 `F:/数据`，上市公司控制变量路径见项目现有记录；先核实磁盘和文件是否可用，不沿用历史“送修/不可用”状态，也不把上市公司金融/ST 筛选套到其他研究对象。



涉及爬虫/LLM 数据时，复用已登记的数据字典和验证清单，由 README 或 CLAUDE 链接；尚无时在对应原任务包建立一份：记录来源时间、覆盖与缺失、抽样人工比对、Prompt/模型/参数、误差及局限。既有阈值沿用项目约定；新阈值需依据研究对象明确，不能用通用默认值冒充验收结果。



### 2. 创建必要目录和项目说明



读取实际模板，再生成 README.md、CLAUDE.md，按需复制通用规范。已有文件按本任务首次修改留一次原字节和指纹；更新相关有效正文并删去被本次替代的矛盾规则，不整份覆盖用户编辑内容，也不重复追加历史补充。



README 只回答：当前权威稿是哪份、论文表格怎么跑、特征化事实怎么跑、已采用排版表在result/table和图在result/figure、上游重建和环境要求在哪。代码/数据流水线放 CLAUDE.md；明细放两张清单，不在根目录新建多份“入口/建议/导航v02”。


### 3. 整体研究版本确认或明确核对要求后生成可独立运行的do

**计算与核对分开（2026-10-08用户更新）**：数据/变量调整、筛选、全套结果重跑和导出默认只用Python；已有最终面板、参考Word或历史do不触发Stata运行。要求“重跑全部结果”“生成最终面板”或文件名含“定稿”，均不等于确认本轮最终研究版本。用户明确确定最终研究版本后，冻结输入与设定，再生成/同步最终逐表do用于核对Python结果；直接要求Stata/do核对时依明确范围执行。Python缺少接口不自动回退Stata，不用另一估计量冒充既定方法。下列do独立运行、原生样本与验收要求只在这个核对阶段适用；Python阶段保存完整结果、协方差、实际样本与日志，目录分类仍照常执行。初始化和整理文件不自动授权新实证。

未采用但用户明确要求Stata/do核对时，先定位并复用本研究问题的测试任务目录，所有do和本轮01设置都生成在同一包；把每个模板首个do加载语句中的正式do/01绝对路径改为该包内01的真实绝对路径，禁止加载正式目录旧设置。TASK_DATA_PATH使用data/temp中的真实数据任务路径，TASK_STAGE未采用时填trial，DO/CODE/RESULT/TABLE/FIGURE和日志均指向分类测试包，TEMP另指data/temp中的数据任务；输入可只读引用既有源，新增DTA与中间文件集中data/temp；测试包登记引用。运行前逐项展开检查；采用后才按范围生成正式路径。

do按工作顺序编号，固定开头为：

```text
00_导入原始数据与构建.do
01_统一设置.do
02_变量定义.do
03_描述性统计.do
04_逐步加入控制变量的基准回归.do
05_具体检验主题.do
……
主程序.do                     # 可选，只按顺序调用上述文件
```

- 00专用于导入原始数据与构建，01专用于统一设置，02进入变量定义，03进入描述性统计，其余按论文分析顺序接续。文件序号是工作顺序，**不强制等于论文表号**；每个分析do在文件开头及测试/分析类别/YYYYMMDD_文件管理/图表对应.csv登记真实表号。辅助图和其他分析也接续编号、写清内容。主程序.do是调用入口，不另占00；不得再生成00_统一设置或00_主程序。
- 每张论文表一个明确现用do，包含该表全部列、真实样本记录、保存估计及获授权的导出段；同表模型不分散到多个文件。文件名采用两位工作序号_具体主题，不能只写编号、T编号、表4或机制一。改名同步主程序、生成/打包脚本及两张清单，历史日志和正式快照保留当时名字。
- **最终do核对与文档导出授权分开。** 所有do模板的RTF等排版导出段仅为获授权后才能启用的示例，默认注释；生成器只有在用户明确授权相应表和格式后才生成可执行导出命令，并核实输出范围与旧版归档。最终研究版本确认、生成do或Stata核对都不自动授权导表；未授权时只保存计算结果、实际样本及核对记录。
- **每个数据构建或分析do先do读取01_统一设置.do，再显式use或import自己的输入。** 逐表do默认use统一设置里的PANEL；专用输入也必须在该文件显式读取。使用绝对设置路径完成首次加载，不能依赖尚未定义的$DO。主程序是否运行过、前一个do留下的数据、宏、frame、postfile句柄或程序，均不能成为运行前提。
- 01集中REPRO、ROOT、DATA、RAW、TEMP、FINAL、DO、CODE、RESULT、TABLE、FIGURE、LOGROOT、年份、控制变量$X、PANEL、面板键、FE、聚类、回归公共选项、统一标签，以及save_sample_ids等共用程序和其他必要共用设置。沿用现有项目变量时点和设定，不从模板推定。01不use数据、不做回归、不清空已加载数据，也不重置随机种子；随机算法使用已约定的种子并显式记录。
- **核对任务使用独立路径。** TASK_NAME_DATE是原测试证据包名；继续、采用及获授权重跑保持该值；TASK_DATA_PATH在候选与采用阶段均指`data/temp/`内已登记的真实数据位置，TEMP指向该相对路径；LOGROOT指向测试任务，保留运行证据。PANEL_RELATIVE_PATH显式指向实际读取或新建的面板，不能固定绑定final。先查目标或归档旧输出，核对不覆盖冻结输入。
- 00先读01再从已登记来源导入，处理中间件写本轮TEMP。候选及采用的合成DTA均集中data/temp并登记状态，只有另获最终冻结授权才另存final。PANEL显式选择真实输入或未占用的新输出，不重复原始构建，不覆盖既有版本。
- **do给研究者看。** 00和逐表do开头先写简短阅读路线：输入、处理顺序、关键公式/单位、样本限制和输出；每个重要合并旁注明来源、键和缺失处理。用有含义的名称与中文分段标题，让研究者能只看本文件找到Y、当期控制变量、政策时点和最终样本。减少与任务无关的模板警告和隐藏关键步骤的抽象；不能为缩短行数把研究口径挪进难追踪的黑箱。修改后由不依赖上下文的读者核对是否看得懂；代码变更须另验运行结果。
- **每份do含参考表头。** 在首个 `**#` 书签及命令之前，用 `/* ... */` 列出 `project`、`Author`、`E-email`、`Creation Date`、`Modification Date`、`Do-file version`、`References`、`Input`、`Output`；输入/输出写实际文件；每份分析do自行加载设置和输入，不把主程序会话作为依赖。未证实的作者、邮箱、原创建日期和原版本写“未记录”，不得复制示例作者信息或把磁盘时间当成原创建日期。模板也保留全部字段，生成时按真实项目填写；只改注释时明确版本口径未变并核对可执行命令。
- **所有do正文都带Stata书签。** 参考用户现有do文件，用独占一行的 `**# 01 小标题`，不要把 `* === [书签…]` 普通注释当作书签。编号在单文件内唯一并随执行顺序递增；构建或主程序的长段再用 `**# 04.1 合并某来源` 等子书签区分每个来源、模型方法或表。逐表do至少让读者直接找到输入/样本、估计和导出，短文件按实际部分设置。模板也必须示范这种写法；生成时替换成项目真实的小标题，动态填入的每个独立来源或模型组也要补子书签。验收时在Stata Do-file Editor的书签导航中检查，并核对标题与实际步骤一一对应；如果本轮只加书签，逐字核对原有执行命令不变。
- **禁用preserve/restore这一对数据现场命令。** 数据切换写清save到TEMP和use哪份文件。保存真实e(sample)时可由01定义的共用程序frame put真实观测键、保存至TEMP后drop该frame；不要为保存ID破坏回归现场。允许estimates store、estimates save和estimates restore；估计对象存TEMP，仍须保留实际样本ID。
- 通用辅助程序只在01实现一次。表专用交互、分组、筛选与差异检验留在对应do。每个do自行打开/关闭唯一日志并记录完整输入输出，不引用主程序独占的未打开句柄。
- 独立验收：新开Stata会话，仅运行某个逐表do，能够读取设置和输入、运行全部约定模型、保存真实样本及估计对象；只有相应格式获明确授权时才导出该表，未授权时保留底表与核对记录。只检测到do/use命令不等于已实际通过独立运行。

`templates/do/05–09`及相关系数模板是可选内容模板，按论文实际表数拆取；编号按真实顺序调整。02变量定义表若为人工文字，标明人工来源；若由代码产生，配置VARIABLE_DEFINITION_CODE_BLOCKS，不伪造计算结果。全部约定特征化事实逐图登记，并由Python直接计算、绘图和核验，不生成或调用特征化事实do。

逐表模板中的DO_STEM是工作序号加主题，TABLE_ID是实际论文表号，两者分别填写。为01提供真实面板键、FE、聚类和控制列表；为模型配置实际e(sample)记录，非e(sample)估计器按接口取真实行。未替换占位符或缺少输入的文件标为未就绪，不能报告可一键复现。

### 4. 运行产物直接按用途落位

- TEMP在各阶段均指向data/temp中的真实数据位置；日志写本任务LOGROOT。用户采用且已授权导出的表格/图进入TABLE/FIGURE；不自动写FINAL，不依赖主程序残留状态。
- 未采用的新数据与数据缓存集中data/temp，程序、表图、日志和文档集中分类测试包；部分采用仅提取对应必要链条到正式目录，原测试包保留。正式do/code仍平铺；文档不迁入初稿。
- 重估、重导或替换正式面板前，为被替代正式版留一份可恢复归档，再更新现用材料。候选及采用的底表、样本ID和对象均集中data/temp；已采用部分即使验收通过仍属temp，不自动提升final。高成本中间数据明确保留，维护两张清单。
- 不把路径调整当作改变Y、样本、变量时点、FE、聚类或运行新回归的授权。分别报告结构、独立do执行、估计对照及图表重跑的实际完成状态。

4. **验收**：核对迁移前后文件映射、数量与指纹，初稿和图表原字节保护；检查现用 README/清单的本地链接、程序输入存在性、旧根残留及动态路径风险。把现用可执行引用与历史文本旧路径分开报告。按授权做必要只读入口或语法检查，不因目录迁移重跑估计、绘图或大库。分别报告文件完整性、静态引用、实际入口检查、估计重跑、图表重跑及全量原始重建的真实状态，静态通过不能称全部可复现。

5. **清理**：现有文件经审查、用户确认清单、隔离、下一次相应复现通过后才永久删除。原始数据、人工修正、全国评分等高成本数据、正式非显著结果不得按 tmp/old/日期早机械删除。同一清单已有授权时不反复确认；新候选需要新授权。

6. **交付**：只给一个当前入口，说明迁入/归档/隔离/永久删除各多少、保留什么、验收范围和未解决项。磁盘问题报告逻辑大小和实际释放空间，硬链接不能重复计为可释放空间。

## do整改的实际验收（2026-10-08补充）

本节约束最终确认后或用户明确要求的do核对/整改；日常Python重跑不触发新Stata会话。

- 用户要求统一控制变量时，必须实际打开现用01_统一设置.do，确认存在可执行的`global X 真实变量列表`；只有skill写了要求、主程序有X、注释列了控制变量，都不算落实。通用FE、聚类、标签、PANEL和辅助程序也逐项核对。
- 按用户当日要求逐项检查现用do：00构建、01设置、02变量定义、03描述统计；每个分析do先加载01再use/import输入；禁止preserve/restore数据现场命令；全部正文有原生`**#`书签及完整参考表头。
- 独立运行须从新Stata会话开始，不能预先运行主程序补宏、数据、frame、句柄或估计对象。引用已保存数据/估计时写清文件路径；共享模型在本表显式估计或读取真实保存对象。每份do创建、关闭自己的日志和postfile。
- 同步检查旧生成脚本：不得从历史快照覆盖整改后的现用do。改名须同步调用、导航和图表对应清单；旧入口退出do并保留原字节归档。
- 数据现场save/use替换后，核对辅助program的局部宏作用域。公共路径用全局TEMP，不能让外层local在program内展开为空并把文件写到磁盘根。
- 验收逐项报告已改、实际运行通过、尚未验证的范围。静态命令和字节检查不能替代运行；发现遗漏不能沿用上轮“已完成”的表述。


**特征化事实使用Python。** 不在现用do目录生成或保留特征化事实do，也不让do或实证主程序调用其计算。Python入口应从冻结输入直接构造逐图数据、绘图并核验，不能要求先运行Stata生成CSV。do只保存实证链所需的构建、设置、变量定义、描述统计、回归与识别图、结果提取。历史事实do原字节可归档，不能继续作为现用入口。
