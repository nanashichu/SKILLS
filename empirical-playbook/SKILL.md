# 实证顶刊做法库与不显著诊断

## 0 边界与优先级

- **规则优先级：** 用户本轮明确指示 > 项目 README、CLAUDE 与实际设置 > 本 skill > references。
- **只读：** 本 skill 读取项目代码、日志、结果底表、样本记录和稿件，检索文献，输出诊断与借鉴方案；**不改代码、不跑回归、不建或改数据**。用户选定方案后，按 [empirical-research](../empirical-research/SKILL.md) 在原测试包中估计并全量保存；目录与任务包按 [empirical-project-init](../empirical-project-init/SKILL.md)。
- **默认研究设定沿用 empirical-research S9**：基准四列、统一样本 `sample == 1`、机制一步法（只估 X → M）、`$控制变量`、do 不用 capture、esttab 保留常数项、不导 LaTeX。文献做法与 S9 不同时（三步中介、分样本各用各的样本、只报最严格一列等），在方案中写明差异，由用户决定，不自行改默认。
- **诊断默认只在对话给出。** 用户要求保存时，写入该问题原任务包（沿用原包与原开始日期）的 `诊断与借鉴方案.md`；没有原包时按 S2 判断类别后询问是否新建。
- **改 skill 本身**（入库新做法、修改 references）属于修改用户 skill：用户明确要求“入库/更新方法库”时直接写；只要求“看看顶刊怎么做”时先在对话汇总，再问是否入库。写入后提示同步到 GitHub 仓库 `nanashichu/skills`。拿不准的设计取舍先问，不按自己判断改。

## 1 两种模式

| 模式 | 典型说法 | 产出 |
|---|---|---|
| **A 检索入库** | “看看顶刊稳健性现在怎么做”“多时点DID顶刊怎么写”“更新方法库” | 对话里按部分汇总常见做法/较新做法/本项目可用性，附来源；确认后写入案例卡库 |
| **B 不显著诊断** | “第4列不显著了”“机制做不出来”“异质性没差异”“审稿人说IV太弱” | 诊断表 + 候选方案表（出处、所需数据、实现、风险等级、与 S9 差异）+ 建议顺序与预先登记清单 |

模式 B 中发现方法库缺某类做法，或用户要求“找顶刊依据”，转模式 A 补检索后再给方案。

## 2 模式 A：检索与入库

1. **定检索单元**：部分（基准/异质性/稳健性/内生性/机制/进一步分析）× 识别设计（面板FE、DID/多时点DID、IV、RDD、PSM、事件研究…）× 研究对象（上市公司、城市、个人…）× 结果类型（如盈余管理、投资效率、创新）。
2. **检索**：按 [期刊与检索指南](references/journals-and-search.md) 的期刊清单和检索式，中文、英文分别检索；应用案例近 5 年优先，方法文献不限年份。英文先查方法文献与指南性综述，再查应用论文。
3. **读到相应章节才记做法**。能读全文的记“全文”，只有摘要的记“仅摘要”，公众号/知乎/课程等二手来源只作线索，入库前找一手来源核对卷期。CNKI 和部分期刊官网会拒绝自动抓取或要求验证码，换可读来源；仍读不到时请用户上传 PDF 或粘贴章节，或在用户已登录的浏览器中读取。
4. **写案例卡**（格式见 [案例卡库](references/case-library.md)）：只记可迁移做法——做了什么、针对哪种威胁、需要什么数据、估计量/命令、怎么报告。用自己的话概括，不抄原文段落，引语最多一句且少于 15 字词。
5. **去重入库**：同一做法已有卡片时只追加出处；新做法同时补进对应部分文件（`references/0X-*.md`）的做法清单与“不显著时可借鉴”表。
6. **对话汇总**：按部分列“中文顶刊常见 / 英文顶刊与方法文献要求 / 本项目能否用（数据、设计是否满足）”，末尾列来源链接。

## 3 模式 B：不显著诊断

### 3.1 先读材料，不凭描述臆断

读取：结果底表与日志（b、SE、p、N、簇数、FE、控制、真实样本）、对应代码、变量定义与样本筛选记录、稿件中的理论预期与方向。缺结果表或设定时先向用户要，不猜。区分“不显著”“方向相反”“估计失败/未识别”——失败不是不显著。

### 3.2 看显著性模式，定优先怀疑方向

| 现象 | 优先怀疑 | 对应文件 |
|---|---|---|
| 无 FE 显著、加 FE 后不显著 | FE 吸收了 X 的大部分变异；或无 FE 时的显著来自遗漏变量。**不能靠去掉 FE 解决** | [基准](references/01-baseline.md) |
| 加控制后消失 | 坏控制（处理后变量、机制变量当控制）；或原结果由遗漏变量驱动 | [基准](references/01-baseline.md) |
| 系数大小合理但 SE 大 | 功效不足、聚类层级与处理层级不匹配、簇少、FE 过饱和 | [诊断树 L4](references/insignificance-diagnosis.md) |
| 系数接近 0 且置信区间窄 | 可能确实没有效应，准备按 L7 如实报告 | [诊断树 L7](references/insignificance-diagnosis.md) |
| 多时点 DID 的 TWFE 不显著或反号 | 处理效应异质导致的负权重；效应滞后 | [稳健性](references/03-robustness.md) |
| 全样本不显著、理论只预期部分群体有效应 | 异质效应相互抵消 | [异质性](references/02-heterogeneity.md) |
| IV 第二阶段不显著、OLS 显著 | 弱工具、2SLS 方差大；或 OLS 有偏 | [内生性](references/04-endogeneity.md) |
| X → M 不显著 | M 的测度、时点、FE 吸收；渠道理论本身 | [机制](references/05-mechanism.md) |
| 分组系数一显著一不显著 | 组间差异未必显著；须做正式差异检验 | [异质性](references/02-heterogeneity.md) |
| 某项稳健性失效 | 该项改变了什么（样本/度量/估计量/推断） | [稳健性](references/03-robustness.md) |
| 进一步分析不显著 | 可能本身就是信息（排除某种解释） | [进一步分析](references/06-further-analysis.md) |

### 3.3 按诊断树逐层排查

按 [诊断树](references/insignificance-diagnosis.md) 从 L0 到 L7：**L0 代码与数据 → L1 测度与时点 → L2 样本与支持 → L3 设定（FE、控制、函数形式）→ L4 推断与功效 → L5 识别与估计量 → L6 理论与异质性 → L7 接受并报告 null**。前面的层级是“纠错”，越往后越接近“改研究设计”，需要越强的事前依据。每层标明哪些检查能从已保存结果只读完成，哪些需要新估计（列入方案，交 empirical-research）。

### 3.4 匹配可借鉴做法并评级

从对应部分文件的“不显著时可借鉴”表与案例卡库挑选，每条方案写清：

- **做法**与**针对的问题**（对应诊断层级）；
- **出处**：方法文献或顶刊案例卡（未核实的标“待核对”，不编造作者、期刊、年份）；
- **所需数据/新变量**，项目里是否已有；
- **实现**：Python 估计量或 Stata 命令名（Stata 只用于最终核对阶段）；
- **风险等级**：
  - 🟢 **纠错/提高质量**：修正代码错误、坏控制、残差两步法、聚类层级按设计改正、换用对多时点处理稳健的估计量、更精确的公认测度；
  - 🟡 **需事前依据的改变**：换 Y/X/M 代理、改时点、理论驱动的分组、换样本窗口、换 FE 结构——必须写出制度或理论理由，且原口径结果照样报告；
  - 🔴 **仅为显著而改**：无依据删样本、事后挑分组阈值、去掉 FE、只报显著的代理、单尾检验——列出“为何不建议”，不进入候选清单。
- **与 S9 的差异**（如有）。

### 3.5 交付与交接

按第 5 节模板输出，等用户选择。用户选定后，把**全部候选规格清单（含预期方向）先登记**，再交 empirical-research 估计；结果按其规则全量保存、显著与不显著一并汇报、按模块做多重检验校正（见 empirical-research 项目经验§3）。

## 4 红线

- **先定清单再跑**：候选规格在看到结果前列好；不按 p 值挑结果，不只报显著的。
- **显著性变化必须定位来源**：样本、测度、估计量还是推断改变带来的，逐项说清。
- **不为显著而**：无制度/数据依据删样本、事后改分组阈值或窗口、把机制变量当控制、去掉 FE、改聚类层级来缩小 SE、换显著的代理却不报原代理、用单尾检验、把 10% 显著当主要证据而不说明。
- **聚类与推断按设计选**：聚类层级取决于处理分配和抽样方式，不取决于哪个 p 更小；簇少时用 wild cluster bootstrap，结果可能更不显著，照实报告。
- **真实无效应时如实报告**：置信区间、最小可检测效应、等价检验，说明对文献的含义（Abadie 2020）。
- **文献引用只用读到的内容**；概括用自己的话。

## 5 输出模板（模式 B）

```markdown
### 一句话判断
（例：第4列不显著主要因企业FE吸收了X约90%的变异，属设计识别力问题，不是代码错误。）

### 诊断
| 层级 | 检查 | 发现 | 证据位置 | 是否需新估计 |

### 候选方案
| # | 做法 | 针对问题 | 出处 | 所需数据 | 实现 | 风险 | 与S9差异 |

### 不建议的做法（🔴）及原因

### 建议顺序与预先登记清单
1. 先做🟢纠错项 ……
2. 有事前依据的🟡项 ……（写明理由与预期方向）

### 若仍不显著：报告方式
（置信区间、MDE、等价检验、写法要点）
```
