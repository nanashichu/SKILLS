## 跨对话搜索与日志更新（§10 核心）

### 触发条件

"结束工作"、"更新日志"、"今天干了什么"

### ⚠️ 时间戳来源规则（关键！禁止估算）

| 会话类型 | 时间戳来源 | 方法 |
|---------|-----------|------|
| 其他会话（非当前） | `search_recent_sessions.py` 输出 | 脚本从 JSONL 提取 UTC→北京时间 |
| 当前会话 | 当前 JSONL 文件 | Read 当前会话的 JSONL，提取 `type: "user"` 消息的 `timestamp` 字段 |

**禁止行为**：
- 禁止凭感觉编造当前会话的时间（如"大概19:00-20:00"）
- 禁止把当前会话的工作全部合并为一条无时间的条目
- 当前会话结束后，时间戳必须从 JSONL 读取，和其他会话一样的流程

**为什么**：2026-06-05 当前会话实际工作时间为 21:57-23:00，但 Agent 编造了 19:00-20:10，差了两个多小时。根因是 `search_recent_sessions.py` 只搜其他会话，当前会话的时间被跳过了。


跳过 `claude-mem-observer` 目录。

### 搜索流程

1. 扫描所有项目目录，用 mtime 粗筛（目标日期 ±1天）
2. 解析 JSONL，提取 `type: "user"` 消息
3. **UTC → 北京时间（+8h）**，按目标日期筛选
4. 过滤噪音：skill加载、command-message、中断信号、长度 ≤5
5. 排除当前会话 ID

### 结果分流

| 内容类型 | 写入位置 |
|---------|---------|
| 项目相关工作 | `projects/对应项目.md` 📅项目日志 |
| 工作时间线 | `daily/YYYY-MM-DD.md` 🕐时间线记录 |
| 已完成任务 | `daily/YYYY-MM-DD.md` ✅今日已完成 |
| 非工作内容 | `daily/YYYY-MM-DD.md` 💭今日感悟 |
| 新项目/新skill | 新建 projects 文件 |

### 时间线合并去重

- 先读取已有时间线
- 只补充未记录的时间段
- 按北京时间排序

### 项目关联识别（AI Agent 判断，禁止关键词匹配）

⚠️ **脚本不做项目归类**。`search_recent_sessions.py` 只输出原始消息（时间/会话/文本），项目归属由 AI Agent 根据以下维度综合判断：

1. **消息内容**：任务描述、文件名、提到的项目名
2. **会话上下文**：该消息所在 JSONL 文件的其他消息（通过 session ID 关联）
3. **项目列表**：读取 `projects/` 目录了解已有哪些项目

**禁止行为**：
- 禁止用单一关键词匹配项目（如看到"爬虫"→法拍房）
- 禁止只看消息片段不看完整上下文
- 不确定归属时标注"待确认"而非强塞到某个项目

### 🧭 Skill 使用回顾优化（§10 附带，自动触发）

**触发时机**：每次"更新日志"/"结束工作"完成跨对话搜索和结果分流后，自动执行。

**目的**：复盘今天实际用什么工具做了什么事，对比 task-optimizer 的推荐值，发现优化空间。

**执行步骤**：

1. 从今天时间线 + 已完成任务中提取实际执行的任务列表
2. 对每条任务，判断实际用到的 skill/工具（从 JSONL 对话中识别 `Skill` 调用或任务描述推断）
3. 用 task-optimizer 框架重新分析每条任务该用什么 skill 链
4. 对比实际 vs 推荐，输出优化建议：

```
🧭 今日 Skill 使用回顾

| 任务 | 实际使用 | 推荐工具链 | 差距 |
|------|---------|-----------|------|
| Copula尾部相依 | 手动写do文件 | empirical-research | ⚠️ 下次直接用empirical-research，自动生成do模板+Stata-MCP执行 |
| 审稿意见回复 | chinese-academic-paper:revision | ✅ 完美匹配 | — |
| 搜论文 | 手动WebSearch+下载 | paper-search | 💡 下次用paper-search一键搜+导出Excel |

💡 优化建议：
- 今天X个任务中，Y个有对应skill但未使用 → 下次直接用
- Z个任务无现成skill覆盖 → 可考虑新建或扩展现有skill
```

**输出位置**：终端输出（附在经验教训区块后），不写入 daily/projects 文件（避免日志膨胀）。

**约束**：
- 简单任务（单步、无skill需求）不强行分析，标注"直接做，无需skill"
- 不推荐不存在的 skill
- 回顾结果如果全是"✅ 完美匹配"则精简为一行，不展开表格

## 缓存优化机制（§7 核心）

### 缓存文件

`memory/project-tasks-cache.json` — 所有项目的任务摘要

### 重建触发条件

- 缓存不存在
- `lastUpdated` ≠ 今天
- 缓存版本过期

### 重建流程

1. 扫描 `projects/*.md` 所有文件
2. 提取：进度、未完成任务、截止日期
3. 写入缓存，更新 `lastUpdated`

### 读取策略

生成今日待办最多 2 次读取（daily + 缓存），不逐个读项目文件。

## 任务时间预测（§4 附带）

### 预测算法

```
基础预测 = 同类任务历史平均用时（从 task-time-history.json 读取）
置信区间 = [预测值 × 0.8, 预测值 × 1.3]
```

## 经验教训自动生成（§9）

### 生成流程

1. 读取今日时间线 + 已完成任务
2. 按类别分组提炼

### 分类

| 分类 | 涵盖内容 |
|------|---------|
| 实证方法 | 回归设定、检验选择、数据处理决策 |
| 工具使用 | Stata/Python/Claude Code 操作技巧、踩坑 |
| 项目管理 | 时间分配、优先级判断、协作 |
| 论文写作 | 结构、表达、逻辑 |
| 其他 | 以上不覆盖的 |

### 标记体系

- ✅ 做得好的：今天什么有效
- ⚠️ 需改进：什么可以更好
- 💡 新发现：学到的新东西
