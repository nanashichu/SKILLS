# 日周月待办联动管理系统 v6.3

## 执行合约

- **Start**：接收触发词 → 日期校验 → 读缓存判断增量 → 执行对应功能（开始工作/更新日志/结束工作/周报/风险检查）
- **Support**：`memory/project-tasks-cache.json`、`G:\【20260401】每日待办\daily\`、`G:\【20260401】每日待办\projects\`、search_recent_sessions.py、sync_feishu.sh
- **Check**：日期是否正确（禁止凭记忆）？daily 和 projects 是否双向同步？日志五要素是否完整？经验教训是否非空？跨对话搜索是否已跑？
- **Avoid**：凭当前会话记忆判断项目进展（必须跑 search_recent_sessions.py）、日志区块漂移（必须回读模板验证）、重复打卡、空经验教训区块

## ⚠️ 日期校验规则

**每次操作前必须确认当前日期！**

```
当前日期获取方式：
1. 系统提示中的 currentDate
2. 或使用 dayjs().format('YYYY-MM-DD')

日期计算规则：
- 今天 = 0天
- 明天 = 1天
- 截止日期 - 今天 = 剩余天数
- 周一 = 本周第1天，周日 = 本周第7天
```

**常见错误：**
- 混淆日期（如把4月19日说成4月20日）
- 周几计算错误（如把周五说成周四）
- 剩余天数计算错误

**正确做法：**
- 生成待办前，先明确输出"今天是 YYYY年MM月DD日 周X"
- 涉及日期计算时，先确认再输出

## 🚀 缓存优化

**核心原则：生成今日待办只需读 2 个文件，不逐个读项目文件！**

### 缓存文件
`memory/project-tasks-cache.json` — 所有项目的任务摘要

### 缓存自动重建

**触发条件：**
- 缓存文件不存在
- 缓存 lastUpdated != 今天
- 缓存版本过期

**重建流程：**
```
1. 运行 python scripts/scan_projects.py
2. 缓存自动写入 memory/project-tasks-cache.json
3. lastUpdated 自动更新为今天
```

⚠️ **缓存过期时，必须先跑脚本再读缓存，不要手动逐文件扫描。**

| 场景 | 读取文件 |

| 生成某天日志 | claude-mem优先 → JSONL回退 → 合并已有时间线 |

## 🌅 每日工作触发

**触发条件：** 用户说"开始工作"、"早上好"、"开工"、"今天开始工作"

**执行步骤（优化后，最多读3个文件）：**

1. 如缓存过期（lastUpdated != 今天），先运行 `python "G:/【20260401】每日待办/scripts/scan_projects.py"`
2. 读取 `daily/YYYY-MM-DD.md`（今天）
3. 读取 `memory/project-tasks-cache.json`（缓存）
4. 检测是否有实证任务（关键词：回归、面板、Stata、数据、基准回归等）
5. 如有实证任务，随机选择一种激励风格输出
6. **§11 风险预警（自动触发）**：检查是否有紧急deadline（3天内）、逾期任务、效率异常，如有则在待办前输出预警
7. ⚠️ **写入 daily 文件（不可跳过）**：
   a. 从缓存 `incompleteTasks` 中筛选 priority="高" 或 status="加急" 的任务
   b. 取 3-5 条最高优先写入 `### 🔥 今日重点`，其余写入 `### 其他任务`
   c. 用 Edit 替换 daily/YYYY-MM-DD.md 中 `## 📋 今日待办` 下的 `（暂无）`
   d. 每条严格使用 checkbox 格式：`- [ ] **[项目名]** — 任务描述 | ⏰ 截止日期（如有）`
   e. 写入后确认待办条目 total > 0，否则网页仪表盘 `parseDailyLog()` 仍显示"暂无待办任务"
   为什么不可跳过：仪表盘只解析 daily 文件的 checkbox 行，不读缓存/项目文件。终端输出 ≠ 文件写入。
8. **🧭 task-optimizer 路由分析**：对每条今日重点任务，应用 task-optimizer 的分类+复杂度+匹配矩阵框架，输出推荐 skill 链和提示词优化要点。非简单任务的每条都必须有路由推荐。
9. 输出今日任务概览（含路由推荐）
10. 🔴 **CHECKPOINT**：写入后 Read 确认 `## 📋 今日待办` 下存在 ≥3 条 `- [ ]` checkbox 行，且无残留 `（暂无）`。验证不通过 → 回到步骤7重写，直到仪表盘可解析。

## 文件操作规范

### daily 文件增量规则
- ✅ 可更新：`## 📋 今日待办`
- ✅ AI生成：`## 📝 经验教训`（结束工作时AI自动生成，分类展示）
- ✅ AI提取：`## 💭 今日感悟`（AI从对话中提取用户非工作内容，分类展示）
- ❌ 不可覆盖：`## 🕐 时间线记录`、`## ✅ 今日已完成`
- ❌ AI绝对不碰：`## 📓 今日日记`（用户手写区块，AI不得修改、删除或添加内容）

### ⚠️ 打卡记录防重复规则（关键！）

写入打卡前**必须执行以下检查**：

```
1. Read daily/YYYY-MM-DD.md
2. 检查 ## 🕰️ 打卡记录 下已有的时段区块（上午/下午/晚上/凌晨）
3. 对同时段：更新已有数据，不追加新区块
   例：已有"### 上午 - 上班：09:00"，用户说"上午下班12:00"
   → 更新该区块的下班时间，不新建第二个"### 上午"
4. 对不同时段：追加新区块
   例：已有上午区块，用户说"下午上班14:00"
   → 在上午区块后追加"### 下午"区块
5. 绝对禁止：同一时段出现两个区块（如两个"### 上午"）
```

**每次打卡操作后，必须验证文件中没有重复时段区块！**

### ⚠️ 经验教训强制生成规则（关键！）

`## 📝 经验教训` 区块**不得为空或缺失**。AI在"结束工作"时自动生成，**必须分类展示**。


触发时机：用户说"结束工作"时，自动从今日时间线+已完成任务提炼，按类别（实证方法/工具使用/项目管理/论文写作/其他）分组，每条标记 ✅做得好的 / ⚠️需改进 / 💡新发现。**禁止空区块**。完整规则见 references/features.md §8-§9。

### ⚠️ 结束工作/更新日志强制自检规则（关键！）

**触发时机：** "结束工作"、"更新日志"、"补充日志"完成后，**报告完成前必须执行自检**。

**自检流程：**

```
1. Read daily/YYYY-MM-DD.md（写入后回读确认）
2. 逐板块检查以下 8 项，输出状态清单：

   🕰️ 打卡记录   [✅已填 / ❌空白 / — 无需填]
   🕐 时间线记录 [✅已填 / ❌空白]
   📝 经验教训   [✅已填 / ❌空白]
   💭 今日感悟   [✅已填 / ❌空白]
   📋 今日待办   [✅已填 / ❌空白]
   ✅ 今日已完成 [✅已填 / ❌空白]
   📋 明日待办   [✅已填 / ❌空白]
   📓 今日日记   [— 用户区块，不检查]

3. 判断规则：
   - 打卡记录：用户未打卡时标记"— 无需填"，不强制
   - 今日感悟：搜索JSONL无非工作内容时标记"— 无内容"，不强制
   - 日记：永远不检查
   - 其余 5 个板块（时间线/经验教训/今日待办/已完成/明日待办）：❌空白必须当场补齐

4. 只有所有板块状态为 ✅ 或 — 时，才能报告"更新完成"
5. ❌空白板块未补齐前，禁止说"完成"或"结束"
```

**为什么这一步不可跳过**：2026-05-27 日志几乎所有板块空白（今日待办/已完成/明日待办全空），5/28 时间线和经验教训全空。根因是 Agent 写完时间线后未逐块对照模板自检，直接报告完成。自检清单强制逐项确认。

**错误示例：**
```
Agent: "日志已更新完成"  ← 未输出自检清单，禁止这样说
```

**正确示例：**
```
Agent: "自检：🕰️打卡 — | 🕐时间线 ✅ | 📝经验教训 ✅ | 💭感悟 — | 📋待办 ✅ | ✅已完成 ✅ | 📋明日 ✅ | 📓日记 —
全部通过，更新完成。"
```

### ⚠️ 已完成自动填充规则（关键！）

**写时间线的同时必须写已完成。时间线 = 已完成的来源，两者是同一数据的两面。**

```
写入 🕐 时间线记录时，每条工作内容同步追加到 ✅ 今日已完成：

  时间线条目：- **14:00-15:00** [知识产权法庭] - 跑05_稳健性检验.log → 导出4张合并表
      ↓ 同步生成
  已完成条目：- [x] [知识产权法庭] 05_稳健性检验全部跑通→导出4张合并表

规则：
1. 时间线和已完成必须同时写入，不允许"先写时间线，待会再补已完成"
2. 同一条工作不拆成多行已完成——一行时间线对应一行已完成
3. 非工作类时间线（会议、讨论、阅读）也需同步到已完成
```

**为什么这一步不可跳过**：2026-05-27 时间线写了8条详细记录，但已完成完全空白。Agent 把时间线和已完成当成两个独立步骤，写完时间线就停了。两者是同一数据的不同视图，必须联动写入。

## 失败模式与恢复

| 触发条件 | 一线修复 | 仍失败兜底 |
|---------|---------|-----------|
| `search_recent_sessions.py` 不可用 | 检查 Python 路径 | 降级：Agent 手动读 daily/ 和 projects/ 文件 |
| 跨对话搜索脚本超时 | 缩小搜索范围（只搜最近 3 天） | 基于当前会话记忆总结 |
| daily 文件模板与预期不一致 | 回读 CLAUDE.md 模板，逐区块对比 | 按模板重建缺失区块 |
| 打卡时间与已有区块重叠 | 检查已有时间线区块，更新而非追加 | 标注"时间段重叠，已合并" |
| projects/ 文件与 daily/ 不同步 | 从时间线逐项提取项目，全部同步后报告 | 列出不一致项，让用户选择保留版本 |
