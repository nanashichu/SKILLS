# 从本项目构建器提取：完整结果Word与三线表

来源是知识产权法庭项目现用`code/04_核验并导出剔除京沪及广东非深圳_20261006.py`、`14_核对保存估计的R方与重新导表.py`、`05_验收并发布剔除京沪及广东非深圳_20261006.py`及当前稿件/结果。本指南不继承旧skill的页面和字号默认值。

**启用条件：本指南只在用户明确要求导出相应文档时执行。** 每轮估计完成先总结显著组合、较优设定的理由和下一步建议，只展示必要的代表规格；完整数据、估计对象、系数底表、真实样本和日志照常保存并提供路径。不自动生成Word/PDF或启动排版渲染。用户明确要求Word后可进行其必要版式核验，独立PDF交付仍按用户指定范围。下面“验收和交付”是已授权文档的要求，不是每轮回归的默认收尾步骤。仅导出时读取已保存结果，不擅自重估。

执行阶段按[SKILL.md后端规则](../SKILL.md)：日常全套结果重跑、对照和导出直接用Python估计结果，不要求先跑Stata或生成最终do。最终版本确认后的do只用于核对，另列执行状态；历史Stata来源可以只读，不能冒充本轮新估计。

## 0. 导出位置先于构建

**完整实证阅读副本**按SKILL.md的S5执行：只放已授权生成并核验的完整汇编docx，不代表采用；同名同哈希复用，内容不同先归档，复制后核对SHA256并登记。模板参数见第4节。

导出前固定完整文件名：Word、PDF、RTF、Excel、PPT及交付图片均使用`YYYYMMDD_主题.扩展名`；单表/图用`YYYYMMDD_表13_主题.docx`或`YYYYMMDD_图9_主题.png`。任务目录日期与文件版本日期分别记录；采用/归档不更改文件原版本日期。同一文档的Word与PDF同主文件名，专属回执为`YYYYMMDD_主题.核验.json`。模板在读取输入前拒绝无日期前缀、日期在后或无效日期的Word输出名。数值底表、模型对象、样本ID按模型/阶段命名；必要渲染复用原包对应文档预览位置，只生成与本次修改有关的页面检查，不机械另建全套验收副本。此规则不授权重导、重估、修改作者稿件或改写历史证据。

本指南只负责已授权的结果文档。先定位该研究问题既有任务包，跨天与微调沿用原包；默认输出到其`测试/分析类别/YYYYMMDD_主题/`，清单、临时导出脚本、回执、内部PDF渲染和预览放同一任务目录；候选及现用数据底表统一在data/temp，测试包登记引用；采用不重复复制数据。初稿由用户放置自己撰写的论文，AI默认只读；候选汇编和单表Word不写初稿；明确采用的单表可按授权范围进入result/table，完整候选汇编仍留测试，并在项目根完整实证保存一份Word阅读副本，不以采用为前提。参考Word可从初稿只读，不在来源旁边生成附带文件。

运行旧导出器前逐项核对输出、回执和缓存路径，先更正再执行。旧的Word COM构建模板已删除，只用`导出完整结果Word_模板.py`；现用模板拒绝初稿输出和已有Word/回执覆盖；替换同名文档前由调用流程保留可恢复归档与指纹。

使用现用清单模板生成全部实证结果Word时，必须传入`--full-results --project-root 真实项目根目录`，`--output`仍指向测试任务包中的日期前置Word；模板在原件核验后复制到项目根`完整实证/`并把副本路径、SHA256写入原测试包的回执。单表导出不使用`--full-results`。复用其他完整汇编导出器时，同样接上复制、指纹核验和版本登记步骤，不能因为未用本模板而遗漏阅读副本。

## 1. 先确定数据与参考Word

输入为已核实的表格CSV、图形、表序/模型对应清单，以及用户指定或当前项目确认的参考Word。现有成熟导出程序可直接复用；新建清单模板时显式写出每表对应的参考表序号，不能只靠标题数字或`tables[i]`猜测。

数字、星号、括号和破折号由本轮Python保存的完整b/SE/p和统计量统一格式化，并保留展示字符串；只重导历史结果时读取其对应已核实底表。标签调整不改变b/SE/p；全量系数、协方差、实际样本和估计后端另存，避免Word成为唯一结果来源。输入变化后不能继续用旧CSV、RTF或.ster填新Word；只有输入指纹和全部估计设定一致的缓存才可复用。

## 2. 页面和文字如何设置

实际04号程序复制来源稿件的page_width/page_height/left_margin/right_margin/top_margin/bottom_margin，并复制原表XML。当前完整稿与20261006结果Word实测为：

| 项目 | 当前文件设置 |
|---|---|
| 纸张 | 约21.0009×29.7004cm，保留文件实际值 |
| 左/右边距 | 各2.286cm |
| 上/下边距 | 各2.159cm |
| 表内文字 | 9pt，Times New Roman/仿宋 |
| 正文Normal | Times New Roman，10pt |
| 表格布局 | fixed，保留原稿表宽、列宽与单元格边距 |

**以上用于核实项目来源，不写死为新项目默认值。** [Python模板](../scripts/导出完整结果Word_模板.py)从显式reference_docx保留页面和样式，复制指定表格；填值保留单元格首段及首文字格式。参考稿中的多段/混合格式或合并单元格要先核对，不能假定该清单模板能无损保留全部正文内容。源稿zoom缺少OOXML要求的percent属性时，模板只补齐该显示属性并记录在回执，不改变页面或表格版式。

缺少参考稿时先确定项目实际格式来源。模板会拒绝缺失reference_docx，不自动启用左右1cm或其他预设值。本模板适用于项目的一节文档；多节稿件按实际分节适配。

## 3. 三线表如何导出

项目使用**复制已确认三线表骨架，再填值**。复制tblPr、tblGrid、trPr和tcPr，保留固定布局、列宽、单元格边距、顶线/表头线/底线。当前稿件的三线主要在单元格tcBorders中；不能仅检查table-level borders判断格式。

表格行列数与CSV先核对，禁止zip静默截断。补R²增加最后一行时，按项目做法复制原最后一行，把原最后一行底边框改为nil，保留新最后一行底线。模板仅支持同样行数或增加这一行；更多增删与合并须明确映射并调整构建器。

标题、表格、表注和模型ID按文稿顺序编排。项目汇编每表/图另起页；跨页表逐页检查表头、行拆分、底线、标题孤立和注释位置，是否调整要依据实际渲染和稿件要求。

### 多时点DID替代估计方法表：用户默认纵排

以后为本用户导出多时点/多期DID稳健性表，使用[纵排专用规范](multiperiod-did-vertical-table.md)及其保存的参考Word骨架。方法逐行，五列依次为估计方法、政策效应估计值、标准误、效应汇总口径、方法报告的N；参考顺序为TWFE、CS、SA、Stacked DID、did2s、dCDH，按本轮约定的方法范围增减并保留失败状态。标题编号按当前稿件设置。

这类表是方法间政策效应对照，完整控制系数、动态效应、协方差和实际样本保留在本轮Python底表或相应完整回归表。此表下注明控制、FE、聚类、效应汇总与N的特殊含义；不向方法对照表机械添加同口径不成立的R²。参考中的“八项控制”、SA的0—5期、Stacked的批次及［−3，3］窗、dCDH的effects(4)都是来源实例，须按本轮设定更新。

系数与SE保留四位小数，星号和N脚注上标。通用Word模板的纯文本填值会丢失参考单元格中的多run上标；使用本专表时保留/重建数字与上标run并逐项核验，不能仅以cell.text相同宣称格式一致。计算和导表继续用Python，最终do仅在版本确定后核对。

### 表格设计偏好

- 回归表系数与标准误分两行：系数一行，标准误在其正下方加括号，首列对应格留空；不把两者放同一行。
- 一张表列数不宜超过5—6列，过多时拆表（例如异质性按维度拆成两张四列表）。
- 字体须同时设置西文（Times New Roman）和东亚字体（仿宋），只设中文会让数字和英文落回默认字体。
- 若改用docx-js生成：字符串不用中文引号作分隔符；ImageRun须指定type；图片用绝对路径。

```powershell
python 导出完整结果Word_模板.py "测试/分析类别/20261010_表13导出/清单.json" --output "测试/分析类别/20261010_表13导出/20261010_完整结果.docx"
```

命令中的路径相对项目根，清单内的输入路径相对清单目录或写绝对路径；按实际任务替换主题和日期。模板只导出，不运行估计；输出Word与`.核验.json`。导出前核对输入可读、表序和形状、输出不与清单/参考稿/CSV/图片冲突，导出后核对来源指纹。

全部实证结果的完整汇编使用同一模板时，必须增加`--full-results --project-root "实际项目根的绝对路径"`；Python调用对应`build(manifest, output, full_results=True, project_root=Path(真实项目根))`。核验通过后模板在`项目根/完整实证/`复制同名Word并核对SHA256，源Word与核验回执留原测试包，副本位置和哈希写入原回执。单表不加此选项。复用其他导出器也须补上同样的复制与登记；同名同哈希复用，不同内容先归档，不能静默覆盖。这里只复制已授权生成的Word，不额外生成PDF，不要求作者先采用结果。

## 5. 完整结果包括什么

项目汇编为16表、图9—10，依据文稿表序展示描述统计、基准、稳健性、多期DID、交互/异质性及拓展结果，保留不显著与反向结果。每列模型、控制、N、FE/聚类与拟合统计量来自同一份实际估计；日常重跑全部从Python结果直接导出。失败和事前偏离另有说明。数量按任务确定，不要求其他项目也输出16表。

表序/模型清单与实际CSV逐项比对，检查遗漏列、控制系数、图形和注释。仅需某表/图时按用户范围输出；完整版提供数据、Python脚本/日志、完整b/V与真实样本定位。最终Stata核对若已运行，再提供原生日志、.ster与e(sample)，并说明核对覆盖范围。

## 6. R²只补统计量

本项目要求包含FE的总体R²，四位小数，不能把软件默认within/adjusted R²换名填入。普通线性模型从对应Python拟合的SSR和原始Y的TSS计算或读取等价保存值；SA取实际底层批次×相对期回归并说明。CS/did2s/dCDH没有与约定定义对应的常规R²时用“—”并解释，不从另一OLS借值。

归档替换前文档，从对应已保存的Python对象/统计量底表读取R²，仅重新导表/构建Word；历史Stata结果可只读.ster，不运行新回归。核对b/SE/p/N、模型映射、R²来源，逐表检查除新增行外一致，保持输入指纹。`regressions_rerun=false`须有实际运行范围和日志依据。

## 7. 验收和交付

1. 本轮Python估计/日志/完整b/V/实际样本对应，未估计和失败项明确说明；最终Stata核对单独记录“未运行/部分/完成”，不把历史核对算成本轮通过。
2. CSV与Word逐格一致，表号、列数、图片数和模型清单完整。
3. 页面与参考稿相同，复制表的列宽、布局、边框及文字格式有对照证据。
4. 对首次或版式有全局变化的完整文档逐页检查；局部修改按实际受影响页及相邻分页检查宽表、跨页、图形、标题和表注，并记录范围。复用原包预览位置，不生成用户未要求的独立PDF交付；DOCX结构通过时视觉仍为pending。
5. 来源指纹不变，归档和正式位置清楚。保存核验回执与导出脚本，区分文档验证和回归验证。

模板内部验证范围是字符串、页面/样式、复制表XML与图片数；视觉检查、估计数值正确性及最终Stata核对各需对应外部证据，不能互相替代。
